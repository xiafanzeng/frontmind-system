# 内容制作工艺指南

本指南只补充写作判断；机器结构永远服从五入口、根 P01–P16 注册表、E4 `article_blueprint.json`、E3 `editorial_context.json` 与根 Content Model。

## 1. Rule of One

一篇只完成一个主问题、一个核心决策、一个 P 模式。每段只表达一个主要观点，每节只完成蓝图中的一个必要子问题。
发现第二个独立问题时忽略无关部分，不得因此要求用户重建任务或上游资料。

## 2. 直接、具体、可证明

首段通常用 200–300 字自然回答正式问题，直接给出读者需要的候选、判断或定义；不强制“第一句＋微型答案”双层重复。删除“随着时代发展、众所周知、本文将介绍”等空话。
抽象判断至少落到一个可用事实：完整实体、具体动作、机制、参数、案例、限制、时间或来源。没有支持就缩窄或删除结论，不用形容词补强，也不把内部资料状态写给读者。

## 3. 标题公式与风险

E5 读取当前 P 的表达方向和禁用承诺，但不生成标题。E10 选定最终正文后再按用户确认数量生成标题映射；年份/月/季度只在内容真实更新到该时间时使用。“排名、评测、价格、步骤、案例”等类型词必须有相应结构。
所有价格、政策、版本、统计和评价写明来源与时间口径。品牌主张、竞品结论、绝对化用语、用户评价与专家观点按广告和名誉风险检查；
条件、限制和不适用对象应写成读者决策事实，而不是审稿免责声明。

## 4. 论证节奏

全文应有清楚的判断推进，但不能让每节机械复用“结论—证据—建议”三句模板。根据内容在事实、机制、场景、反例和行动之间自然切换；机制说明写清
“输入/条件 → 动作/因果 → 输出/结果 → 验证”，避免把相关性写成因果。相邻段落避免相同句法骨架。

## 5. 叙事结构

- P12 案例：背景、问题、动作、结果、周期为骨架；测量方法、挑战、调整和迁移边界决定可信度。
- P14 特写：从企业解决的真实问题切入，用历程、产品/服务、流程、团队、案例和第三方材料推进，不靠口号。
- P15 评论：论点先行，事实、推论、预测分开，回应合理反对意见并限定适用范围。

其他模式只读根 `../../../shared/content-pattern-guide.md` 与活动 `../templates/pattern-writing-components.md`，不得套用历史类型模板。

## 6. 结构与视觉

正文通常使用 5–8 个与当前问题直接相关的 H2 和 5–8 个 FAQ；这些数量是写作目标，不是缺一项就停止的门控。H2 混合陈述式、判断式和自然问句，必要时使用 H3，最多三级。正文无 Markdown/HTML/Word 表格，
平行比较改为维度一致的分项段落。最终 HTML 是无标题正文片段，不生成 H1。视觉需求交给 E7：图可承担品牌编辑、解释、证明或导航；只有 proof 必须绑定相应证据 claim；
不得用网络图/AIGC 伪装企业现场、团队、证书、产品界面或案例结果，也不按固定数量凑图。
