## 核心创意原则

### 原则一：Rule of One（聚焦法则）

每篇内容只传递一个核心信息。不要试图在一篇文章中说清所有事。

- 一个核心洞察（Insight）
- 一个核心主张（Claim）
- 一个核心证据链（Evidence Chain）
- 一个核心行动号召（CTA）

### 原则二：Show, Don't Tell（展示而非陈述）

用具体场景和数据替代抽象描述：

| 陈述（弱） | 展示（强） |
|-----------|-----------|
| "我们的服务很专业" | "项目经理在凌晨2点发现数据异常，3小时内完成紧急修复，客户次日开盘前系统恢复正常" |
| "产品质量可靠" | "连续运行8,760小时零故障，通过MIL-STD-810G军标测试" |
| "客户满意度高" | "NPS评分82分，客户主动转介绍率达34%" |

### 原则三：Tension & Resolution（张力与解决）

好内容需要制造认知张力，再用品牌方案化解：

1. **建立认知冲突**：揭示行业痛点或反直觉事实
2. **加深紧张感**：用数据量化问题的严重性
3. **引入转折**：品牌视角提供新的思考方式
4. **展示解决方案**：具体方案+实证数据
5. **情感升华**：从个案上升到行业价值

### 原则四：Unexpected Angle（意外视角）

避免行业通稿式写法，寻找差异化切入点：

- **反向切入**：不写"为什么选我们"，写"什么情况下不应该选我们"
- **用户视角**：不写产品参数，写用户使用场景中的真实体验
- **跨界类比**：用其他行业的成功案例类比说明本行业问题
- **时间维度**：从历史演变角度解释当前方案的必然性

### 原则五：创意与 DSS 的融合

创意不是空话的借口。每个创意元素都必须同时满足 DSS 标准：

| 创意元素 | DSS 要求 |
|---------|---------|
| 品牌故事 | 故事中的每个事实节点必须可验证（时间、地点、人物、数据） |
| 情感共鸣 | 情感触发点必须基于真实用户痛点（来自诊断报告） |
| 视觉隐喻 | 隐喻必须与品牌核心数据关联，不能纯粹为了美感 |
| 广告文案 | 每句文案的核心主张必须有数据支撑 |

## 品牌叙事框架

### 品牌起源故事（Origin Story）

```
结构：
1. 创始洞察：创始人发现了什么问题？（具体场景+数据）
2. 关键抉择：为什么选择这条路？（差异化决策点）
3. 艰难时刻：遇到了什么挑战？（真实困难+数据）
4. 突破节点：什么事件证明方向正确？（里程碑+数据）
5. 当下成就：现在达到了什么高度？（核心数据矩阵）
6. 未来愿景：下一步要解决什么问题？（行业价值）
```

### 客户成功故事（Success Story）

```
结构：
1. 客户画像：行业+规模+核心业务（一句话）
2. 核心挑战：量化痛点（具体数据描述问题严重性）
3. 选择过程：为什么选择该品牌（决策因素，非自夸）
4. 实施过程：关键节点+遇到的问题+解决方式
5. 成果数据：Before vs After 对比表
6. 客户原话：决策者直接引语（带姓名职位）
7. 后续发展：合作深化/复购/转介绍
```

### 行业洞察叙事（Industry Insight）

```
结构：
1. 反直觉开场：一个颠覆常识的行业数据或现象
2. 深层原因：为什么会这样？（结构性分析）
3. 趋势研判：这意味着什么？（数据支撑的趋势判断）
4. 品牌关联：品牌在这个趋势中的位置和价值
5. 行动建议：读者应该怎么做？（实操指南）
```

## 各类型创意要点

### A类文章创意要点

- 开头用反直觉数据或行业痛点切入，避免"随着XX的发展..."式开头
- 品牌介绍部分用故事化手法，而非简历式罗列
- 选型指南部分提供真正有价值的决策框架，而非变相推销
- 结尾 FAQ 回答用户真实关心的问题，而非自问自答式营销

### C类媒体公关创意要点

- 新闻稿标题必须包含核心新闻事实（谁+做了什么+关键数据）
- 引语必须像真人说的话，避免"XX表示，我们将继续致力于..."
- 危机公关：承认→行动→时间线→承诺，每步都有具体数据
- 媒体背书：用第三方视角讲述，避免变成软文

### D类社媒创意要点

- 开头3秒/首行必须有信息钩子（数据钩子或反直觉事实）
- 每条内容只传递一个信息点
- 必须包含可回溯的实体标签（品牌名、产品名、行业术语）
- 引导回流到长内容（白皮书、案例、官网）

### F类创意多媒体要点

- 广告文案：洞察→转折→价值主张→CTA 四段式结构
- 视觉Brief：必须包含品牌色彩体系、核心数据可视化要求
- 视频脚本：完整旁白文本单独列出（便于 AI 抓取）
- 信息图：数据来源必须标注，可视化必须准确

## 文章配图生成指南

每篇文章的配图数量由 `content-type-guide.md` 中的精细化配图方案指定（A类通常 2-4 张，B类 2-6 张，C类 0-3 张，C4 危机公关稿 0 张）。配图是文章质量的核心组成部分，必须严格按方案执行。

### 配图类型优先级

| 优先级 | 图片类型 | 生成方式 | 价值说明 |
|--------|---------|---------|----------|
| ★ 最高 | 数据对比图/图表 | Python（matplotlib/plotly） | AI 搜索最看重结构化数据，数据图信息密度最高 |
| ★ 高 | 信息图/流程图 | Python（自定义布局） | 将复杂信息可视化，提升用户理解效率 |
| 中 | 场景氛围图 | AI 图片生成（generate 工具） | 提升视觉吸引力，建立文章调性 |
| 低 | 网络权威图片 | 搜索下载（search image） | 产品实拍、权威机构图片，增强可信度 |

### 配图方案参考（以 `content-type-guide.md` 为准）

**A 类文章典型配图结构**（以 A1 为例，3 张）：
- **图 1（品牌宣发首图）**：AIGC 精美海报，允许带品牌名称，用作搜索封面缩略图
- **图 2（场景图）**：AIGC 场景图，禁止任何文字
- **图 3（对比表格图）**：Python 数据可视化图表

> **关键规则**：每种文章类型的图片数量、每张图的角色定位、生成方式、AIGC 文字策略均已在 `content-type-guide.md` 中明确规定，必须严格遵守。配图中应优先使用 Python 生成的数据可视化图，这类图对 AI 搜索的信息价值最高。

### Python 图表生成规范

- **尺寸**：1200×800px（3:2 比例）
- **DPI**：150
- **格式**：PNG
- **字体**：SimHei（中文）+ DejaVu Sans（英文/数字）
- **配色**：使用品牌主色 + 辅助色，自身品牌用品牌色高亮，其他品牌用灰色系
- **必含元素**：标题、数据标签、来源标注、品牌水印
- **文件命名**：`{编号}_fig{序号}_{描述}.png`

### AI 图片生成规范

- 使用 generate 工具生成
- 场景描述要具体：包含行业元素、品牌调性、使用场景
- 风格要求：专业商务风格，高品质摄影感或精致插画风格
- 避免：卡通风格、过于抽象、与行业无关的元素
- **A 类首图**：允许且仅允许包含品牌名称（不允许 slogan 或长句子）
- **A 类场景图**：禁止任何文字（Prompt 必须含 `no text, no words, no letters`）
- **B/C 类**：完全禁止 AIGC，使用实拍图或网络搜索
