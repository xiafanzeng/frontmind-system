# 企业图片库与视觉资产政策

## 1. 轻量可用资产索引

企业 Pack 已有 [registries.schema.json](../../shared/registries.schema.json) 的 `image_registry` 时可直接使用；无 Registry 时也可从实际文件建立当前任务的轻量候选索引。不要求全部图片登记、生成运行时 Registry 或建立跨阶段文件指纹。只对终稿实际使用的图片检查来源、权利、可读性、尺寸和重复使用。

## 2. 来源

- 企业 Logo、产品、团队、场地、证书、客户现场、事件和案例实图必须来自企业提交或明确授权来源。
- 官网下载图与客户提交图分开标记；第三方图片需要许可和署名条件。
- 生成图只能作为解释、流程、比较或数据视觉，不能冒充真实人物、场景、客户、认证、事件或产品外观。

## 3. 自动整理

E1/E7 可扫描没有 manifest 的 job-local 图片库，自动识别尺寸、类型、候选标签和重复文件，但不得推断权利已获得。权利未知的图片不进入终稿；该图被跳过后继续纯文字成稿。哈希只可用于当前文件去重或安全读取，不得成为后续阶段继续条件。

## 4. P 模式要求

- P02/P03：比较图必须与正文使用相同维度和数据来源；P01 禁止竞品比较图。
- P05/P11：机制、架构和流程图必须对应真实组件或步骤。
- P10：数据图标明样本、单位、时间和来源。
- P12：案例图必须绑定授权项目；匿名规则与正文一致。
- P13：事件现场图必须来自该事件的一手或授权记录。
- P14：品牌、团队与环境图必须真实且权利明确。
- P16：视觉克制，以正式 Logo、事实时间线或状态说明为主。

## 5. 缺图与质量门

需要事实性图片但没有合格素材时，可在 warnings 列明所需对象、用途、规格与权利要求，同时继续纯文字交付。不得以网图、图库图或生成图偷偷替代。

E7 每张实际使用的图必须明确属于 `brand_editorial|navigate|explain|prove` 之一；只有 `prove` 需指向 E6 已保留的事实和来源，`explain` 可只绑定章节概念。E8/E10 只检查实际使用图片的正文语义、来源、权利、尺寸、alt 与实际画面一致。
