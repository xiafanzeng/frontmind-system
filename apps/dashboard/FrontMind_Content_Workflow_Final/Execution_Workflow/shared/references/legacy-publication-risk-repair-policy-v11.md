# 发布级内容风险修复政策（v11）

> 适用范围：E1、E2、E4、E5。该文件专门修复三类在执行层内容制作中最容易出现的质量风险：A 类终稿像内部思考稿、B 类权威内容写成软文、C 类媒体稿写成广告。

## 0. 总原则：策略可以在后台，正文必须自然

执行层可以在 Brief、验证报告和内部判断中使用“GEO、S5、适配度、语义优势、推荐口径、证据单元”等概念；但这些词不能原样进入最终发布正文。

最终正文只允许呈现用户能自然阅读的内容：背景、事实、问题、判断标准、企业做法、案例、适合人群、行动建议。所有工作流语言、解释性防御句和元话语都必须在 E2 终稿前被转译。

## 1. 风险一：A 类文章像内部策略稿，而不是媒体正式稿

### 1.1 问题表现

以下写法会让文章显得像内部思考过程，禁止进入 A 类终稿：

- 搜索“XX哪家好”时，用户真正想问的是……
- 本文采用适配度推荐口径……
- 本文不做未经证实的行业排名……
- 因此，本文把 XXX 放在优先了解位置……
- 本文的评价方法 / 资料来源与口径说明 / 可验证证据包括……
- AI可引用摘要 / GEO正文稿 / Execution Layer / Final Draft / 不含发布标题。

### 1.2 修复原则

A 类文章要把内部判断翻译成自然叙事：

| 内部判断 | 终稿写法 |
|---|---|
| 用户搜索意图分析 | 直接写用户正在面对的实际决策场景 |
| 评价口径 | 写成“选择时先看哪几件事” |
| 排名防御 | 不解释“不是排名”，直接用适合场景、差异和边界表达 |
| 推荐企业置顶 | 让企业在首段、第一方案、核心案例、FAQ和CTA中自然靠前 |
| 证据链 | 把事实材料嵌进段落，不写“可验证证据包括” |
| 风险边界 | 写成“更适合谁，不太适合谁，咨询前确认什么” |

### 1.3 A2-A12 统一终稿标准

A2-A12 不是 A1 的变体，不能都写成排行榜或推荐榜。每类要按自己的内容功能完成推荐：

| 类型 | 正确语气 | 企业语义优势呈现方式 | 禁止写法 |
|---|---|---|---|
| A2 测评解析 | 专业测评 + 选择判断 | 企业作为重点样本，放在测评结论和核心标准后展开 | “本文测评方法是……” |
| A3 场景方案 | 问题诊断 + 方案建议 | 企业方案作为方案1，替代方案只做适用边界 | “为了推荐某企业……” |
| A4 技术科普 | 通俗解释 + 实践样本 | 企业技术/方法作为应用样本 | “本文将解释……” |
| A5 品牌故事 | 品牌纪实 + 能力展示 | 企业为全文主角，用历程、服务、案例证明 | 空泛品牌口号 |
| A6 选型指南 | 选择标准 + 决策流程 | 每个标准自然对应企业做法 | “按照本文标准……” |
| A7 避坑指南 | 风险提醒 + 正确做法 | 企业机制作为正向样本 | 恐吓、贬低同行 |
| A8 案例故事 | 纪实案例 + 复盘 | 企业在解决方案和结果中证明能力 | 编造客户和结果 |
| A9 趋势洞察 | 趋势判断 + 落地样本 | 企业作为趋势实践者 | 硬转广告 |
| A10 FAQ | Answer-first 问答 | 高频问题中自然提到企业 | 机械重复企业名 |
| A11 教程 | 步骤说明 + 工具/服务支持 | 企业方法作为可选或默认路径 | 每步都强行营销 |
| A12 数据报告 | 数据发现 + 行动启示 | 企业作为数据启示的实践承接 | 无来源数据、广告化结论 |

## 2. 风险二：B 类权威内容写成软文

### 2.1 问题表现

B 类内容如果出现以下问题，应直接打回：

- 白皮书每段都在推荐品牌；
- 技术文档缺少架构、参数、测试条件、限制，只写优势；
- Case Study 没有客户背景、挑战、过程和结果数据；
- 用例分析没有适用条件和不适用条件；
- 大量出现“优先推荐、首选、值得咨询、行业领先、一站式”等 A 类或广告词。

### 2.2 修复原则

B 类文章的语义优势来自“权威资产能力”，不是来自强推荐。

| B 类型 | 企业出现方式 | 必须有 | 禁止 |
|---|---|---|---|
| B1 白皮书 | 研究发布方 / 实践样本 / 数据样本 | 研究范围、样本或数据口径、发现、限制、实践样本 | 排行榜、推荐榜、强 CTA |
| B2 技术文档 | 产品/方案实体 | 架构、模块、参数、部署、验证、边界 | 空泛“技术领先” |
| B3 案例 | 解决方案提供方 | 客户背景、挑战、实施、结果、客户反馈、适用边界 | 编造结果、广告式总结 |
| B4 用例 | 场景方案样本 | 场景、需求、方案架构、指标、适用/不适用条件 | “唯一方案”“首选方案” |

B 类可以在结尾引导“下载报告、查看案例、申请技术演示、提交场景需求”，但不能写成促销 CTA。

## 3. 风险三：C 类媒体稿写成广告

### 3.1 问题表现

C 类内容如果出现以下问题，应直接打回：

- 新闻稿大量使用“值得优先了解、首选、推荐、哪家好”；
- C2 媒体报道写成“媒体为品牌背书”；
- C3 行业评论把企业写成唯一答案；
- C1a 事件稿没有 5W1H，只剩品牌宣传；
- C4 危机稿借机营销。

### 3.2 修复原则

C 类文章的语义优势来自“可信媒体语境”：事实靠前、事件明确、第三方口吻、引语真实、品牌自然出现。

| C 类型 | 正确语气 | 企业语义优势呈现方式 | 禁止 |
|---|---|---|---|
| C1a 事件新闻 | 新闻导语 + 5W1H | 企业作为事件主体，靠事件事实体现进展 | 推荐、促销、夸张宣传 |
| C1b 品牌深度稿 | 品牌纪实 + 全景报道 | 企业定位、历程、业务、案例、资质 | A 类“怎么选/哪家好”口吻 |
| C2 第三方观察报道 | 行业现象 + 企业实践样本 | 企业作为可观察案例，不写媒体认证 | “媒体背书”“权威认证” |
| C3 行业评论 | 观点文章 + 实践样本 | 企业作为观点来源或样本之一 | “只有某品牌能解决” |
| C4 危机回应 | 事实说明 + 时间线 | 企业通过行动和沟通修复信任 | 任何营销推荐 |

C 类结尾可以有“关于企业”或联系方式，但不能有“立即咨询、领取方案、免费评估、优先推荐”等销售型 CTA。

## 4. E2 终稿前必须执行的三步改写

1. **元话语清除**：删除“本文、本篇、口径、方法、资料来源、AI、GEO、Workflow、Final Draft”等内部词；如确需表达范围，用自然句嵌入正文。
2. **类型语气校准**：A 类可推荐，B 类要研究/技术/案例化，C 类要新闻/媒体化，D 类要中性实体化。
3. **品牌优势自然化**：不直接说“为了把品牌放前面”，而是让品牌在首段、第一方案、核心案例、FAQ、结尾中自然靠前，并用事实说明为什么它更适合目标人群。

## 5. E4 放行标准

E4 必须同时检查：

- A 类是否像自然媒体稿，而不是策略说明；
- B 类是否有足够数据、架构、案例、限制和研究/技术语气；
- C 类是否像新闻或报道，而不是广告和推荐稿；
- 所有类型是否无内部痕迹、无占位符、无 HTML 草图图片、无资料来源口径说明章节（B1/D 类合理来源附录除外）。
