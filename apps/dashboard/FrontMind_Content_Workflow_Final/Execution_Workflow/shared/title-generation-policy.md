# 标题生成政策

## 1. 同题候选

E10 在最终正文确定并从 `job_state.json` 取得 1–20 的 `title_count` 后，为同一无标题 Content Model 生成独立 Title Map。标题数量是五类内容确认中的最后一项，不生成标题数量回执或文件身份绑定。候选可以改变措辞、切入角度和长短，但不能变成多个选题，也不能承诺正文没有的排名、数据、评测或事件。

## 2. 公式

公式是语义构件，不是固定后缀拼接。内容确实更新到当年时，可以自然组合：`年份 / 地区或人群 / 品类 / 内容形态 / 具体决策问题`，不要求每个标题同时出现全部构件。核心品类通常位于前半部分。价格、政策与版本使用具体年月或季度，避免无依据的“最新、近期、新版”。同批标题必须具有实质不同的角度和句法。

## 3. 模式词

- P01：单品牌推荐、为什么值得考虑、适合谁；
- P02：品牌推荐、候选名单、编辑推荐；
- P03：对比、区别、如何选择；
- P04：评估、口碑、可信度；
- P05：是什么、原理、功能；
- P06：场景、解决方案、适用；
- P07：价格、选型、采购指南；
- P08：教程、步骤、操作指南；
- P09：风险、限制、替代、避坑；
- P10：研究、白皮书、调查；
- P11：技术文档、架构、实施；
- P12：案例研究、项目复盘；
- P13：事件事实；
- P14：品牌深度特写；
- P15：行业评论、专家观点；
- P16：事实说明、处理进展、回应。

标题必须与 [content-pattern-registry.json](../../shared/content-pattern-registry.json) 的 purpose 一致。Title、H1 建议、Meta 和正文首段必须同题；它们只存在于 Title Map 和发布元数据，不能回写无标题正文。
