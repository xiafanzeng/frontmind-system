# 受众决策情境方法

本方法由原营销图谱中真正影响文章质量的部分收敛而来。目标不是做一份大而全画像，而是识别读者在某个决策时刻需要哪些信息和证据。

## 1. 基本单元

```text
决策情境 = 角色 × 触发事件 × 要完成的任务 × 约束 × 决策标准
```

- **角色**：使用者、影响者、技术/合规把关者、预算拥有者、最终决策者；同一人可兼任。
- **触发事件**：出现问题、替换方案、扩张、合规变化、成本压力、技术迁移等。
- **任务**：读者真正想推进的进展，而非产品动作。
- **约束**：预算、时间、兼容性、能力、风险、组织流程。
- **决策标准**：选择时用于排除、比较与确认的明确标准。

## 2. 从资料到情境

1. 从 knowledge registry 找到已出现的用户、使用场景、问题、产品能力与限制。
2. 从客户说明提取决策角色；无法验证的画像标 `hypothesis`。
3. 用 claim/source refs 区分“已知需求”与“营销人员推断”。
4. 合并只有措辞差异、决策标准相同的情境。
5. 优先保留能改变文章信息顺序或证据类型的情境。

## 3. 场景层次

可用四类场景帮助查漏，但不作为新的全局枚举：

- 功能使用：完成具体任务；
- 情境触发：时间、地点、事件或组织变化触发；
- 决策比较：预算、采购、替换、验证；
- 情感/身份：信任、风险感、专业认同。

## 4. 决策标准模板

每个标准记录：`criterion`、`why_it_matters`、`minimum_evidence`、`knowledge_ids`、`claim_ids`、`status`。`status` 区分 `validated`、`client_asserted`、`hypothesis`。

“性能好”“服务专业”不是标准。改写成可观察条件，例如响应范围、兼容边界、资质范围、交付周期、可验证案例或限制条件。

## 5. 质量门

- 人口属性不能替代决策角色。
- 产品功能不能直接替代用户任务。
- 每个 context 至少两个会改变文章内容的决策标准。
- 每个高优先级 context 至少有一个可用 proof bundle；没有则进入 research gaps。
- 不在 S4 生成用户会问的完整问题；S7 根据这些情境建问题库。
