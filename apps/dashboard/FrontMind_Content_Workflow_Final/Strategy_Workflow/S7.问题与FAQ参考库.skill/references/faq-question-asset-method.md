# FAQ 问题资产与 Provenance

本方法承接原 S2 的“用户—场景—意图”与两层问题框架，但只围绕已确定的企业决策问题整理可复用 FAQ 资产。

## 两层整理

1. **核心决策层**：读者要完成什么决定，例如理解、筛选、比较、验证、排险或实施。
2. **具体情境层**：角色、触发、约束、对象、地域、时间与所需证据。

一个可用问题必须同时指向核心决策和具体情境。纯关键词组合没有上下文，纯画像又无法形成可回答问题。

## Provenance 类型

- `user_supplied`：客户/用户直接提供，记录文件、访谈或行号；
- `first_party_observed`：站内搜索、客服记录、销售问题、官方社区，记录定位；
- `external_observed`：公开搜索建议、论坛、问答或评论中的真实表达，记录 URL、时间与摘录；
- `source_derived`：由知识/证据材料中的信息缺口推导，记录 `source_id/knowledge_id`；
- `research_hypothesis`：研究者根据 decision context 推导，必须明确是假设。

Provenance 证明问题从哪里来，不证明答案是真的。答案边界仍须使用 `claim_id` 与 S4 `proof_id`。

## 品牌相关性

FAQ 资产应同时覆盖品类理解与品牌验证问题。不要把每个问题强行塞入品牌名，也不要收集品牌完全无法提供独特、可靠答案的泛问题。

## 质量检查

- 问题自然、具体、单一决策；
- 有真实来源时保存可定位 provenance；
- 有对应 S4 context 时建立连接；
- 按实际情况标意图、入口和候选 pattern，不强制全集覆盖；
- 明确 answerability；
- 无搜索量数据时不伪造数字。
