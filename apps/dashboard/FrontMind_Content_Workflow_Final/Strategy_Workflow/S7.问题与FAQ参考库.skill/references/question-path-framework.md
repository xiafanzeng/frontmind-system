# 问题路径与去重方法

## 1. 从决策过程而非关键词列表出发

问题路径描述同一读者怎样从一个不确定性走向下一步决策：

```text
触发 → 初步理解 → 建立标准 → 寻找候选 → 比较/验证 → 风险确认 → 行动准备
```

这不是固定意图枚举。每个问题仍必须使用共享 registry 中的 `question_intent_tags`，并以 `entry_category` 引用五个 canonical content entries。

## 2. 问题生成矩阵

对每个 S4 decision context 交叉检查：

- 哪个概念需要先解释？
- 选择标准是什么？
- 哪些候选或替代方案需要比较？
- 价格、实施、兼容或限制是什么？
- 哪些证据能建立信任？
- 哪些失败、争议或风险必须主动说明？
- 读者在采取下一步前还缺什么？

问题必须只包含一个核心决策。复合问题拆成多个 question，但通过 `path_group_id` 保持关系。

## 3. 去重

两个问题若以下三项相同，则通常应合并：

- 核心决策；
- 所需证据集合；
- 预期回答结构。

品牌名替换、同义词、语序、城市名或“哪个好/怎么选”的表层差异不构成新问题。保留一个 `canonical_question`，其他真实表达进入 `observed_variants` 并分别记录 provenance。

## 4. 路径完整性

高质量路径应能让同一角色完成一次完整决策，但不要求每个角色机械覆盖每个阶段。检查：

- 是否只有认知问题而没有比较、风险或实施问题；
- 是否只有产品功能而没有决策标准；
- 是否大量问题没有任何可用 proof；
- 是否有关键 research gap 但题库假装可以回答；
- 是否问了与品牌能力无关、无法形成高质量文章的问题。

## 5. 优先级

FAQ 关联度不是搜索量排序。使用 `faq_relevance` 只说明问题与既定企业决策场景的关系：核心回答、辅助解释或边缘补充；`relevance_reason` 必须写明依据。没有数据时不得伪造搜索量或把关联度变成制作顺序。
