# Reference Pack 确认表规范

## 工作表

1. **说明与总览**：输入文件、哈希、阶段状态、对象数量、S3 状态、硬门槛结果。
2. **声明与证据**：高价值/高风险 claim 与 proof bundle；显示 publishability、来源、精度、允许措辞。
3. **受众与话语**：decision contexts、核心 message、术语、比较规则、五入口决策口吻与可选文体差异。
4. **问题覆盖**：七意图、五入口参考覆盖、30–50 问题与 provenance/answerability 摘要；`foundation_start` 只审品牌身份/能力 FAQ，不要求监控。
5. **视觉资产**：asset ID、来源、权利、usage mode、槽位与 Logo 规则。
6. **审批决议**：六项确认、总状态、负责人/角色/时间、附带条件、未决风险。
7. **_meta**：机器读取的输入路径与 SHA-256；隐藏且不得人工编辑。

## 可编辑列

对象页末尾固定为：`审核决定`、`修改要求`、`备注`。决定只能 `keep/change/block`。任何 `change/block` 都使最终状态不能是 approved。

## 数据完整性

- workbook 保存每个输入文件的全量哈希，不是每阶段抽样一个文件。
- 每行首列是稳定对象 ID；不能用 Excel 行号作为引用。
- 长文本可以截断展示，但 `_meta` 指向完整 JSON；审批记录保存被审对象 ID。
- 工作簿不回写源 JSON。修改必须回到责任阶段重新产出并重新生成表。

## 条件与风险

本契约不允许“带条件打包”。任何条件、缺证据的核心声明、权利不明图片或未知问题来源均必须 `changes_requested`；修复并重新审核后才能 `approved`。
