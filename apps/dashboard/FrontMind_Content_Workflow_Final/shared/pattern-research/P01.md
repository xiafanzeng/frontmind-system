# P01｜单品牌深度推荐

- 模板版本：`2.3.0`
- 核心问题：在明确品类与需求下，为什么这一个品牌值得优先考虑，它又不适合谁？
- 研究用途：结构、子问题、证据位置、视觉论证、FAQ、优缺点与不可借鉴元素
- 运行边界：本档案只向 E4 提供结构动作；链接不能证明客户、竞品或公共事实。

## 触发条件

- 问题要求推荐一家或解释某品牌为何值得选
- 正文只需要一个焦点品牌且不承诺 Top-N

## 固定专业骨架

| 组件 | 编辑任务 | 读者收获 |
|---|---|---|
| `P01_component_direct_answer` | 直接回答焦点品牌在何种条件下值得考虑，不借榜单语气制造权威 | 读者先获得有条件、可执行的单品牌建议 |
| `P01_component_selection_criteria` | 把品类选择标准写成读者能现场核对的判断动作 | 读者知道推荐依据，而非只看到品牌卖点 |
| `P01_component_brand_fit` | 以事实—能力意义—适合情境展开品牌定位与 RTB | 读者看清品牌为何适合特定需求 |
| `P01_component_delivery` | 用真实流程、使用方式或项目记录说明承诺如何落地 | 读者知道从咨询到交付会经历什么 |
| `P01_component_limitations` | 集中交代限制、不适用对象和替代路径 | 读者能排除不匹配选择 |
| `P01_component_faq` | 回答尚未在正文解决的费用、周期、验证和风险问题 | 读者补齐行动前的关键缺口 |
| `P01_component_conclusion` | 回收选择条件并给出下一步，不增加新卖点 | 读者可以据自身条件决定是否继续了解 |

## 可选模块与证据降级

- `P01_optional_project_example`：存在可公开项目记录；用一段案例验证能力如何落地。证据：项目主体、动作、周期和授权范围。
- `P01_optional_price_snapshot`：存在同一日期和条件的公开价格；说明价格构成而非制造低价标签。证据：币种、版本、日期和适用条件。
- 降级｜缺案例：删除案例模块，以流程和能力事实完成推荐。
- 降级｜缺第三方评价：不写口碑或领先，使用第一方公开事实说明品牌适配。

## 读者问题、反对意见与品牌介入

- 子问题：推荐依据对应哪些真实选择标准？
- 子问题：品牌的能力如何转化为用户结果？
- 子问题：完整使用或交付流程是什么？
- 子问题：哪些条件下不应选择该品牌？
- 子问题：下一步如何验证是否适合？
- 反对意见：这是不是把广告包装成榜单？
- 反对意见：第一方事实能否支撑推荐强度？
- 反对意见：为什么没有同时列出竞品？
- 品牌自然介入：在品类选择标准之后自然引入焦点品牌，让品牌事实逐项回应标准；首段可以先给条件式结论，但不借虚构排名背书。

## 标题与视觉

- 标题公式：{需求}下，为什么可以优先了解{品牌}
- 标题公式：选择{品类}时，{品牌}适合哪些人
- 标题公式：从{选择标准}看{品牌}：能力、流程与适用条件
- 标题公式：{品牌}深度推荐：先看这{数字}个选择条件
- 视觉 `brand_editorial`：品牌首屏；真实品牌资产或不含虚构实物的编辑视觉。
- 视觉 `navigate`：选择标准较多；标准—能力对应关系图。
- 视觉 `explain`：流程或机制复杂；流程图或机制示意图。

## 失败样例与禁止行为

- 失败样例：全文只有焦点品牌卖点清单，却用“排行榜”“最佳”制造第三方权威感。
- 禁止：出现第二个品牌或竞品矩阵
- 禁止：把第一方资料写成市场口碑或行业第一
- 禁止：使用分数、名次或伪测试证明推荐

### P01-B02｜Google guidance for high-quality reviews

- URL：https://developers.google.com/search/docs/specialty/ecommerce/write-high-quality-reviews?hl=en
- 来源类型：`vendor_documentation`
- 语义焦点：高质量评测如何呈现一手体验、可比指标与优缺点
- 页面结构：页面以作者角色开场，主体是一组高质量评测动作，随后补充原创性优先与联盟链接说明。 清单从用户视角、专业知识和一手体验推进到量化、差异、优缺点及最佳结论的证据要求。
- 观察到的子问题：作者如何证明自己真正了解或使用过被评对象？ 为什么某项是特定用途下的更好选择，依据能否独立成立？
- 证据位置：测量结果、体验材料和竞品差异被要求紧邻对应判断，而不是集中放在参考文献区。 涉及最佳、排名或同类优势时，页面要求给出足以支持结论的一手证据。
- 视觉作用：图片、音频和体验链接被定义为使用经历的证明，不是通用氛围素材。 P01 可借鉴真实使用或交付图贴近能力描述的做法；没有真实素材时应省略而非生成伪体验图。
- FAQ 观察：该页是评测检查清单而非 FAQ；P01 正文应先回答选择依据、关键优缺点和适用情境，再把价格或验证动作放入 FAQ。
- 优点：把推荐强度与一手证据、量化结果和具体用途直接连接。 同时要求优点、缺点和竞品差异，能抑制纯卖点式单品牌稿。
- 局限：条目覆盖广但缺少自然叙事顺序，照抄会形成审查表。 规则主要面向商品评测，服务型品牌的交付过程需要另行设计。
- 不可借鉴：没有真实试用时不得借用一手体验、测量或长期使用的口吻。 不得把全部建议逐条改写为 H2，造成机械清单文章。
- 选择理由：该页为 P01 提供事实—判断的最小动作集，尤其适合约束单品牌推荐中的体验证据和优缺点表达。
- 研究说明：2026-08-17 逐页复审：阅读了完整最佳实践清单及联盟链接段，归纳证据动作而未保存原文。

### P01-B03｜Google people-first content guidance

- URL：https://developers.google.com/search/docs/fundamentals/creating-helpful-content
- 来源类型：`vendor_documentation`
- 语义焦点：people-first 内容如何围绕真实任务而非搜索词堆砌
- 页面结构：页面用自评问题组织内容，依次检查内容质量、专业性、页面体验、people-first 目的和搜索优先风险。 后半段以 E-E-A-T 与 Who、How、Why 收束，将作者、制作过程和创作目的连成一套自检框架。
- 观察到的子问题：内容由谁创作，读者能否看见其经验或专业背景？ 文章为什么存在，是帮助真实任务还是为了覆盖搜索词？
- 证据位置：作者信息、来源和事实错误检查被放在专业性问题组内，与信任判断相邻。 涉及健康、财务等高影响主题时，信任要求在 E-E-A-T 段被单独提高。
- 视觉作用：页面几乎完全依靠问题层级导航，没有用插图替代质量说明。 P01 可将 Who、How、Why 转成内部编辑检查，不应把三词框架做成面向读者的流程海报。
- FAQ 观察：大量问句是作者自评工具，并非读者 FAQ；成稿不应把这些内部检查原样公开。
- 优点：把内容是否真正完成读者任务置于关键词覆盖之前。 将作者身份、制作方式和内容目的分开检查，适合发现伪专业表达。
- 局限：它不示范单品牌推荐的章节节奏，也不说明品牌应在哪个位置自然介入。 自评问句密度很高，直接迁移会产生明显的审核报告腔。
- 不可借鉴：不得把 E-E-A-T 当作对品牌信誉或产品质量的认证。 不得将 Who、How、Why 作为正文固定栏目向读者展示工作流。
- 选择理由：该页用于检查 P01 是否回答了真实选择任务，并帮助编辑删除为搜索引擎而写的空泛段落。
- 研究说明：2026-08-17 逐页复审：按质量、专业性、people-first 与 Who/How/Why 的真实章节顺序完成归纳。

### P01-B04｜GQ Recommends: how we test

- URL：https://www.gq-magazine.co.uk/article/how-we-test
- 来源类型：`consumer_editorial`
- 语义焦点：编辑部如何公开测试方法并解释推荐成立条件
- 页面结构：文章先回答为什么值得信任，再介绍编辑团队，随后集中披露独立性、联盟关系和包容性原则。 主体按男装、个护、睡眠、礼品和健身等品类分别说明选择或测试方法，没有强行套用一套指标。
- 观察到的子问题：谁实际负责某个品类，他的经验如何影响评测？ 哪些推荐来自真实使用，哪些只能依赖研究、行业经验或专家意见？
- 证据位置：每位编辑的履历与负责品类相邻，信任来源不只是一句团队专业。 个护等品类写明测试时长、使用对象和判断维度，商业关系则在独立性部分提前披露。
- 视觉作用：团队肖像用于建立责任人，产品使用照片则跟随具体品类测试段落。 视觉有明确图片编辑角色与来源说明；P01 可借鉴真人责任和真实场景，但不能复刻媒体徽章。
- FAQ 观察：页面通过目录与品类分节回答信任问题，没有单独 FAQ；测试方式应留在正文，只有读者行动问题才进入 P01 FAQ。
- 优点：把编辑独立、商业披露与实际测试限制公开说清，可信度来自过程而非口号。 品类方法差异明显，避免将实验室指标错误套到服装或服务体验。
- 局限：团队履历篇幅很长，若用于品牌稿会淹没读者最关心的选择结论。 媒体会直接不收录不喜欢的产品，这种编辑取舍不能替代品牌局限说明。
- 不可借鉴：不得仿用 GQ Recommends 徽章、媒体资历或主观品味为客户品牌背书。 不得把媒体未测试时的信任逻辑包装成客户拥有同等独立评测能力。
- 选择理由：该页适合借鉴责任人、商业披露与品类化方法的排布，帮助 P01 写得像成熟编辑推荐而非品牌自夸。
- 研究说明：2026-08-17 逐页复审：阅读团队、独立性、真实使用及多个品类测试段，记录其不同证据位置。

### P01-B05｜Tom's Hardware review methodology

- URL：https://www.tomshardware.com/news/how-we-test
- 来源类型：`consumer_editorial`
- 语义焦点：硬件评测如何把实验流程、测量项目和结论相邻放置
- 页面结构：页面先提出透明与可复现原则，再按 CPU、显卡、笔记本、显示器等硬件类别列出各自测试方法。 每个品类由测试环境、仪器或基准项目直接支撑结论，并链接到更细的专项方法页。
- 观察到的子问题：实验室基准与评测者日常使用各回答什么问题？ 如何保持不同产品在相同条件下可比，并在驱动或测试套件变化后重测？
- 证据位置：具体基准数量、分辨率、仪器和重复测试方式紧跟对应硬件类别。 异常复测、系统配置和测试环境被写入方法段，使性能结论可以追溯。
- 视觉作用：测试台、测量设备和结果图承担 prove 或 explain 作用，而非品牌氛围装饰。 服务型 P01 不应照搬硬件图表；只有存在可复现数据时才使用同类证明视觉。
- FAQ 观察：页面不依靠 FAQ 补方法漏洞；各品类的测试问题在对应章节解决，P01 可把如何现场核验留作行动型 FAQ。
- 优点：对不同对象采用不同方法，并交代可复现条件，事实密度很高。 量化结果与实际体验并列，避免单一跑分等同完整推荐。
- 局限：高度依赖实验室与硬件语境，不能直接转成一般企业服务推荐。 方法条目多于选择叙事，缺少不适用用户与替代路径的完整收束。
- 不可借鉴：不得虚构基准数量、仪器名称、测试环境或可复现性。 不得将某个性能维度的优势扩大成品牌整体更值得选择。
- 选择理由：该页用于强化 P01 的具体性：每项能力判断都应尽量说明观察条件和结果，而不是堆叠形容词。
- 研究说明：2026-08-17 逐页复审：重点核对总方法说明与 CPU、显卡、笔记本、显示器的分品类测试段。

### P01-B06｜Tom's Guide laptop, tablet and PC testing methodology

- URL：https://www.tomsguide.com/computing/how-we-test-laptops-tablets-pcs
- 来源类型：`consumer_editorial`
- 语义焦点：不同设备类别如何采用不同测试维度而保持可解释性
- 页面结构：文章从 Windows 设备范围与系统准备开始，再按日常性能、显示、电池、游戏等使用任务展开测试。 结尾单独说明测试会随技术变化持续调整，把一次结果与长期维护区分开。
- 观察到的子问题：测试前如何恢复到普通买家实际会得到的设置？ 哪些维度代表日常体验，哪些只在高负载或特定设备上有意义？
- 证据位置：关闭休眠、恢复厂商默认等准备动作出现在任何性能结论之前。 各项基准、仪器与使用观察被放在相应任务段，测试更新说明位于全文收束处。
- 视觉作用：每个大测试阶段配真实设备照片，帮助读者识别对象而不承担结果证明。 若 P01 采用阶段照片，应把性能数据另用图表或事实句表达，不能让产品图替代测量。
- FAQ 观察：没有独立 FAQ；系统准备、测试维度和方法更新已经按流程解决，适合借鉴为交付流程而非问答堆叠。
- 优点：把测试前状态统一放在首位，减少厂商预设导致的不公平结论。 章节围绕真实任务而非规格表，能将技术数据转成使用意义。
- 局限：设备测试步骤很长，对单品牌文章而言需要大幅压缩。 内容集中于电脑品类，没有给出服务体验、售后或组织能力的表达方式。
- 不可借鉴：不得把实验室设置、工具或测试结果移植到没有同等条件的品牌。 不得用大量流程细节延迟 P01 首段的直接推荐答案。
- 选择理由：该页提供先统一前提、再按任务解释表现的顺序，可帮助 P01 把品牌流程写成读者能理解的真实体验链。
- 研究说明：2026-08-17 逐页复审：读取系统准备、日常性能与持续更新章节，未摘录基准原文。
