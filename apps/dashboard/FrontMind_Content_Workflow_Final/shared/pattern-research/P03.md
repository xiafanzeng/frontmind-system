# P03｜明确竞品对比

- 模板版本：`2.3.0`
- 核心问题：已经明确命名的两个或多个对象，差异在哪里，各自适合什么条件？
- 研究用途：结构、子问题、证据位置、视觉论证、FAQ、优缺点与不可借鉴元素
- 运行边界：本档案只向 E4 提供结构动作；链接不能证明客户、竞品或公共事实。

## 触发条件

- 题面明确点名 A 与 B 或有限候选
- 读者需要共同维度下的对称取舍

## 固定专业骨架

| 组件 | 编辑任务 | 读者收获 |
|---|---|---|
| `P03_component_direct_answer` | 先说清不同条件下谁更合适，避免笼统宣布胜负 | 读者立即看到关键取舍 |
| `P03_component_scope` | 锁定对象、版本、地区、时间和比较边界 | 读者确认比较的是同一口径 |
| `P03_component_common_dimensions` | 建立对称且与核心问题直接相关的共同维度 | 读者知道比较为何公平 |
| `P03_component_parallel_objects` | 按同一顺序逐对象写事实，并明确无同口径数据之处 | 读者可以逐项核对差异 |
| `P03_component_tradeoffs` | 解释差异带来的成本、体验、能力或风险取舍 | 读者能把差异映射到自身需求 |
| `P03_component_faq` | 处理迁移、价格、兼容、服务和限制等剩余决策问题 | 读者补齐选前顾虑 |
| `P03_component_conclusion` | 回收已比较维度，给出分情境结论 | 读者得到条件式而非绝对结论 |

## 可选模块与证据降级

- `P03_optional_migration_cost`：从一个对象切换到另一个；分析迁移成本和兼容性。证据：版本、数据和迁移条件。
- `P03_optional_scenario_verdicts`：需求分层明显；按场景给分支结论。证据：各场景均有共同维度支持。
- 降级｜某对象缺同口径事实：保留未知并降低该维度结论，不用对方资料代替。
- 降级｜无法建立共同维度：改为并列介绍或返回重新选择模式。

## 读者问题、反对意见与品牌介入

- 子问题：比较的是哪些版本和时间点？
- 子问题：哪些共同维度真正影响选择？
- 子问题：关键差异会带来什么取舍？
- 子问题：切换或长期使用成本如何？
- 子问题：什么条件下应选 A、B 或其他路径？
- 反对意见：比较口径是否对称？
- 反对意见：是否只突出客户优势、隐藏劣势？
- 反对意见：旧版本数据是否仍适用？
- 品牌自然介入：在统一比较口径建立后，客户品牌与其他对象按同一顺序出现；品牌优势只在对应维度和适用情境中表达。

## 标题与视觉

- 标题公式：{对象A}和{对象B}怎么选？从{核心维度}看差异
- 标题公式：{对象A} vs {对象B}：分别适合哪些需求
- 标题公式：比较{对象A}与{对象B}，关键不只看{表面指标}
- 标题公式：{场景}下选{对象A}还是{对象B}？
- 视觉 `navigate`：共同维度超过三个；对称比较导航图。
- 视觉 `explain`：技术或流程差异复杂；同尺度机制示意图。
- 视觉 `prove`：关键规格决定结论；带来源的规格或数据图。

## 失败样例与禁止行为

- 失败样例：表面上做 A/B 对比，实际只给客户品牌证据，另一方用空项和形容词承接。
- 禁止：比较不同版本却不标口径
- 禁止：用不对称维度制造胜负
- 禁止：把未知事实写成竞品没有能力

- 视觉作用：PDF 主要依靠编号层级和短清单导航，信息密度高而没有营销插图。 统一字段展示和差异提示图标值得迁移，但认可组织名单不能充当对象质量图章。

- 优点：把独立性、商业关系、排序方法和覆盖范围放在同一透明框架内。 规则后接实施例，能直接转成 P03 的编辑检查动作。
- 局限：横向原则面向比较工具运营者，不是面向某一品类的消费者选购文章。 部分原则是否适用仍取决于比较工具类型和当地法规。
- 不可借鉴：不得把原则认可名单写成对某个比较结果的官方认证。 不得照搬法律措辞制造面向普通读者的冗长合规章节。
- 选择理由：该文件为 P03 提供公平、同口径和商业关系披露的底层规则，尤其适合约束有商业优先顺序的对比稿。
