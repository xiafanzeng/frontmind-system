# P06｜场景解决方案

- 模板版本：`2.3.0`
- 核心问题：面对一个具体行业或任务场景，问题如何诊断，方案怎样落地并验证？
- 研究用途：结构、子问题、证据位置、视觉论证、FAQ、优缺点与不可借鉴元素
- 运行边界：本档案只向 E4 提供结构动作；链接不能证明客户、竞品或公共事实。

## 触发条件

- 问题同时包含用户或行业场景与待解决任务
- 需要方案架构和实施路径，而非单纯产品定义

## 固定专业骨架

| 组件 | 编辑任务 | 读者收获 |
|---|---|---|
| `P06_component_direct_answer` | 先给场景化解决方向和成立前提 | 读者快速判断方案是否对症 |
| `P06_component_context_diagnosis` | 还原用户、任务、现状、约束和问题成因 | 读者确认方案面对的是同类处境 |
| `P06_component_solution_architecture` | 把痛点逐一映射到能力、角色和数据流 | 读者看懂方案为何这样组合 |
| `P06_component_implementation` | 给出实施顺序、责任分工、里程碑和效果检查 | 读者知道如何从方案走到结果 |
| `P06_component_fit_limits` | 说明适用规模、前置条件、失败信号和替代路径 | 读者能控制试错成本 |
| `P06_component_faq` | 回答周期、资源、协作、验收和后续维护 | 读者补齐落地条件 |
| `P06_component_conclusion` | 按场景匹配度给下一步，而非泛化成万能解法 | 读者得到可执行的选择建议 |

## 可选模块与证据降级

- `P06_optional_maturity_paths`：不同团队成熟度差异大；给基础、进阶两条实施路径。证据：每条路径的资源和前提。
- `P06_optional_pilot_plan`：可先小范围试点；设计最小试点和验收标准。证据：试点周期、样本和停止条件。
- 降级｜缺效果数据：用过程检查和可观测指标替代结果幅度承诺。
- 降级｜场景信息不完整：采用保守假设并给读者自检问题。

## 读者问题、反对意见与品牌介入

- 子问题：场景中的主要约束是什么？
- 子问题：问题根因位于哪个环节？
- 子问题：方案各能力如何对应痛点？
- 子问题：实施需要哪些角色与资源？
- 子问题：如何判断试点有效或应停止？
- 反对意见：方案是不是套用通用产品介绍？
- 反对意见：落地成本和组织条件是否被忽略？
- 反对意见：效果指标能否实际采集？
- 品牌自然介入：先完成场景诊断，再把品牌能力作为解决架构中的具体角色；不要从品牌功能倒推不存在的需求。

## 标题与视觉

- 标题公式：{场景}如何解决{问题}：从诊断到落地
- 标题公式：面向{用户}的{问题}解决方案与实施步骤
- 标题公式：{场景}采用{方案}前，先看这{数字}个条件
- 标题公式：{品牌}如何服务{场景}：能力、路径与验证
- 视觉 `navigate`：场景因素较多；问题—能力匹配图。
- 视觉 `explain`：多角色协作；方案架构或泳道流程图。
- 视觉 `prove`：有试点数据；带基线与口径的结果图。

## 失败样例与禁止行为

- 失败样例：把产品功能改写成场景标题，没有诊断约束、实施责任和效果检查。
- 禁止：把方案描述成对所有场景有效
- 禁止：没有基线却承诺效果幅度
- 禁止：忽略数据、人员或合规前置条件
