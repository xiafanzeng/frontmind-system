# P13｜事件新闻

- 模板版本：`2.3.0`
- 核心问题：发生了什么新事件，谁在何时何地采取什么动作，对相关人群意味着什么？
- 研究用途：结构、子问题、证据位置、视觉论证、FAQ、优缺点与不可借鉴元素
- 运行边界：本档案只向 E4 提供结构动作；链接不能证明客户、竞品或公共事实。

## 触发条件

- 存在真实、近期且可核验的新事件
- 需要新闻稿或媒体可直接使用的事实材料

## 固定专业骨架

| 组件 | 编辑任务 | 读者收获 |
|---|---|---|
| `P13_component_news_lead` | 用一段导语交代最新事件和最重要的 5W1H | 读者立即知道发生了什么 |
| `P13_component_facts_background` | 补齐时间、地点、主体、事件背景和信息来源 | 读者能确认事件身份与时效 |
| `P13_component_action_product` | 说明发布、签约、上线或行动的具体内容 | 读者知道事件的实质变化 |
| `P13_component_quotes_impact` | 使用可核验实名引语，并解释对用户或行业的现实影响 | 读者获得事实之外的相关性 |
| `P13_component_next_steps` | 列明后续节点、获取方式和更新时间 | 读者知道接下来何时会有新进展 |
| `P13_component_faq` | 回答参与方式、适用范围、发布日期和媒体常见问题 | 读者补齐事件细节 |
| `P13_component_conclusion` | 回收已发布事实，不增加预测或新主张 | 读者留下清晰事件摘要 |

## 可选模块与证据降级

- `P13_optional_quote_block`：有实名授权发言；用引语解释动机或意义。证据：姓名、职务和原始发言。
- `P13_optional_media_facts`：媒体需要快速查证；补充主体简介和联系信息。证据：最新公开事实。
- 降级｜无实名引语：删除引语模块，以事实和影响完成新闻。
- 降级｜后续日期未确定：写明后续渠道，不编造时间节点。

## 读者问题、反对意见与品牌介入

- 子问题：事件的 5W1H 是什么？
- 子问题：相较此前发生了什么变化？
- 子问题：哪些人会受到实际影响？
- 子问题：引语提供了哪些新信息？
- 子问题：后续节点和获取方式是什么？
- 反对意见：这是否只是旧信息重新包装？
- 反对意见：宣传语是否代替了事件事实？
- 反对意见：预测是否被写成已经发生？
- 品牌自然介入：品牌作为事件主体在导语自然出现，随后以动作、产品变化和影响证明新闻价值；公司简介只在尾部简短补充。

## 标题与视觉

- 标题公式：{品牌}{日期/阶段}发布{事件核心}
- 标题公式：{事件主体}宣布{动作}，将影响{人群}
- 标题公式：{品牌}与{合作方}启动{项目}
- 标题公式：{产品/服务}正式{上线/开放}：关键信息一览
- 视觉 `brand_editorial`：事件有发布视觉；真实活动、产品或品牌资产。
- 视觉 `navigate`：时间节点较多；事件时间线。
- 视觉 `prove`：发布内容需证明；真实现场、文件或产品截图。

## 失败样例与禁止行为

- 失败样例：没有新事件，只把公司介绍、愿景和形容词改写成新闻稿。
- 禁止：虚构日期、合作、引语或发布结果
- 禁止：把未来计划写成已完成
- 禁止：使用未经授权的实名引语

### P13-B01｜PRSA guide to press releases that get coverage

- URL：https://jobs.prsa.org/career-resources/finding-talent-9/how-to-write-a-press-release-that-gets-coverage-in-2025-420
- 来源类型：`professional_guidance`
- 语义焦点：新闻稿如何用新闻价值而非宣传形容词争取报道
- 页面结构：页面先用要点概括新闻价值、标题、倒金字塔和多媒体，正文再依次展开 5W、数据与引语、记者匹配、格式、分发和常见问题。 新闻本身是否值得报道被放在写作技巧之前，导语承担完整事件摘要，后文才补背景、影响和发布材料。
- 观察到的子问题：这次发布对组织外部的人有什么及时而具体的影响？ 记者只读导语时，能否获得主体、事件、时间、地点和原因？
- 证据位置：数字、事实和实名引语被安排在对应正文段，用来补充导语而不是重复口号。 页面列出的传播成效数字与案例来源并不都清晰，适合作为编辑提醒，不宜作为客户文章证据。
- 视觉作用：页面建议提供可下载的照片、视频、图表和新闻资料包，视觉服务于记者再使用。 P13 应优先选事件现场、产品实图或数据图；页面的框架插图和站点品牌图不进入成稿。
- FAQ 观察：页末 FAQ 处理新闻价值、AI 摘要、格式与分发等作者问题；P13 只借鉴读者仍会追问的事件细节，不复制写稿教学问答。
- 优点：把新闻价值、5W 导语和倒金字塔连成完整生产顺序。 明确引语应提供解释或影响，而不是复述已经出现的事实。
- 局限：篇幅很长且多处重复同一写作建议，直接采用会稀释事件主线。 若干比例、传播效果和示例缺少就地可核查依据，可信度不宜外推。
- 不可借鉴：不得沿用页面中的虚构组织、人物、报道结果或未经核实的行业比例。 不得把关键词、发布时间或分发技巧写成事件获得媒体报道的保证。
- 选择理由：该页适合为 P13 校准从新闻价值判断到记者可用材料的完整链路，同时提醒编辑剔除宣传形容词。
- 研究说明：2026-08-17 逐页复审：核对摘要要点、新闻价值、5W 导语、倒金字塔、多媒体、分发与 FAQ 章节。

### P13-B02｜Cision guide to writing a news release

- URL：https://www.cision.com/resources/insights/write-news-release/
- 来源类型：`professional_guidance`
- 语义焦点：新闻导语如何压缩事件事实并支持记者快速使用
- 页面结构：长指南先区分新闻稿与一般发布稿并列举事件、产品、声明和人事等类型，再拆解标准组件、内容写法、新闻角度、编辑与分发。 主体从标题和日期行进入 5W 导语，随后用两三段事实、数据与引语扩展，最后落到公司简介、联系信息和行动入口。
- 观察到的子问题：当前事件属于产品上线、官方声明、活动还是人事变化，哪些信息必须随类型改变？ 公告除了告诉读者发生了什么，还解释了何以重要和谁会受影响吗？
- 证据位置：数据、里程碑和归属明确的引语被要求紧随相关主张，联系信息单独收尾。 不同稿型的事实位置不同：产品稿补规格、价格与可用性，活动稿补日期、场地、嘉宾与报名方式。
- 视觉作用：指南把图片、视频和信息图同时用于吸引注意与解释复杂信息，并强调记者需要可用素材。 页面自身的营销图片只作导航；P13 视觉应回到事件原始资产及明确署名。
- FAQ 观察：页面没有独立 FAQ，定义、稿型与操作问题分散在正文；成稿应把稿型写法留在内部，只回答事件参与和后续安排。
- 优点：按发布类型展示信息差异，避免所有新闻都套同一正文。 将中性语气、事实准确、来源归属与记者扫描习惯放在同一结构中。
- 局限：内容覆盖写作、SEO、社交和分发，远超单篇事件新闻需要。 部分例子带明显销售导向，行动按钮也服务于 Cision 产品转化。
- 不可借鉴：不得把指南的营销服务、渠道建议或示例品牌带入事件正文。 不得在没有公开规格、价格或时间表时照模板补齐这些字段。
- 选择理由：该页能帮助 P13 根据事件类型改变事实组合，并把导语、影响、证据和行动入口安排到记者易用的位置。
- 研究说明：2026-08-17 逐页复审：阅读稿型、七个标准组件、5W 导语、新闻角度、编辑及分发部分。

### P13-B03｜Cision investor-relations press-release practices

- URL：https://www.cision.com/resources/insights/investor-relations-press-release/
- 来源类型：`professional_guidance`
- 语义焦点：投资者关系稿如何处理重大信息、数据与合规口径
- 页面结构：页面先解释投资者关系稿的对象与用途，再按标题、重要信息、财务指标、管理层引语和前瞻内容拆解组件。 后半段转向合规、发布时点、财报与并购等新闻类型、常见错误，最后以四个投资者问答收束。
- 观察到的子问题：哪些变化会实质影响股东，利好与不利信息是否同样前置？ 数字属于哪个期间、比较口径和一次性因素，未来表述是目标还是承诺？
- 证据位置：收入、增长、股价等指标被要求与期间和同比趋势一同呈现，异常数字紧跟原因说明。 管理层引语负责解释战略含义；监管披露、财务复核和前瞻限定在发布前单独检查。
- 视觉作用：页面以章节和数字清单为主，通用头图没有证明作用。 投资者类 P13 可使用同期对比表或已发布财务图，但不能用氛围视觉弱化不利数据。
- FAQ 观察：明确设置 FAQ，回答写作实践、样例来源、必要组件与发布责任；其中合规和联系方式应在正文流程解决，不必搬入读者 FAQ。
- 优点：明确不能把坏消息藏在后文，并要求标题与正文数字一致。 把财务事实、管理层解释和未来计划分成不同语义层。
- 局限：部分安全港和监管建议表述过于概括，不能替代具体辖区的法律审核。 指南仍夹带新闻线分发产品推广，且不适用于大多数非上市事件。
- 不可借鉴：不得照搬美国上市公司术语到不适用的地区或主体。 不得将预测、目标、协同效应或管理层乐观判断改写为确定结果。
- 选择理由：该页为 P13 提供重大信息、数字口径和前瞻陈述的特殊结构，适合高影响企业事件的事实排序。
- 研究说明：2026-08-17 逐页复审：核对投资者对象、指标、引语、前瞻信息、合规、稿型、错误与 FAQ。

### P13-B04｜PR Newswire essential press-release components

- URL：https://www.prnewswire.com/resources/articles/components-of-press-release/
- 来源类型：`professional_guidance`
- 语义焦点：新闻稿组件如何安排导语、背景、引语和联系信息
- 页面结构：文章先解释记者为何依赖熟悉结构，再逐项说明标题、日期行、导语、正文、多媒体、引语、公司简介、媒体联系人和行动入口。 组件之后补新闻价值、简洁表达与真实数据，再列宣传语言、埋藏重点、漏联系信息和糟糕排版等错误。
- 观察到的子问题：第一段能否独立概括整件事，正文还需要补哪些日期、价格或日程？ 引语提供了观点和战略语境，还是把事实换一种说法？
- 证据位置：具体数字被放在相关主张旁，日期与地点固定进入日期行，媒体联系人留在稿尾。 公司简介只承担组织背景，不能替代事件本身的证据与外部意义。
- 视觉作用：多媒体被单列为核心组件，既用于提高分享率，也用于解释复杂主题。 P13 可在正文提示原始照片或视频下载位置，但不采用该页的示意图和商业按钮。
- FAQ 观察：页面没有专门 FAQ，而以组件和常见错误覆盖作者疑问；事件读者的报名、可用性或后续更新应另行生成。
- 优点：每个新闻稿组件都有单一任务，导语、引语和公司简介不会相互替代。 直接指出新闻稿不是广告，并用真实数据对抗含糊宣传。
- 局限：标准组件适合媒体发布稿，不等同于面向公众的完整新闻报道。 关于搜索引擎偏好和转化按钮的建议带有平台营销立场。
- 不可借鉴：不得把固定组件顺序机械转换为每篇 P13 的全部 H2。 不得照用示例数字、地点、公司使命或 PR Newswire 的转化文案。
- 选择理由：该页最适合校验 P13 的组件职责和信息层级，尤其能防止用公司简介或引语掩盖真正事件。
- 研究说明：2026-08-17 逐页复审：逐项检查九个发布组件、新闻价值、真实数据与常见错误。

### P13-B05｜Pennsylvania Sea Grant press-release formatting

- URL：https://seagrant.psu.edu/press-release-formatting/
- 来源类型：`university_guidance`
- 语义焦点：高校格式指南如何处理日期、地点和发布标识
- 页面结构：页面从 AP 风格的用途讲起，先整理标点、大小写、数字、字体和引语规则，再进入标题、日期行、导语、正文、公司简介和联系信息。 末段用格式与篇幅问答补充发布细节，整体更像编辑格式手册而非事件叙事模板。
- 观察到的子问题：日期、地点、职务、数字和产品名称能否在整篇保持统一写法？ 首次出现的人名与职务是否完整归属，后续引语是否仍可辨认来源？
- 证据位置：日期和地点在导语开端固定出现，数字与百分比按上下文统一表达。 实名引语首次标全名与职务，并为每位说话者另起段落，便于责任归属。
- 视觉作用：页面几乎完全依靠格式示例和层级导航，没有用图片证明新闻事实。 P13 可借鉴清爽字体和留白，但中文发布不应机械套用英文 AP 大小写与标点。
- FAQ 观察：页末回答标准组件和常见篇幅；这类格式问题属于编辑内规，公开 FAQ 应改为事件时间、地点或参与方式。
- 优点：把日期、数字、职务和引语归属拆得具体，适合终稿一致性检查。 清楚区分新闻格式与装饰排版，强调记者可快速扫描。
- 局限：大量规则服务英文和美国 AP 语境，对中文稿件只能选择性借鉴。 页面域名属于高校项目，但正文广泛转述外部发布规范，原创权威边界有限。
- 不可借鉴：不得把英文标题式大小写、州名缩写和牛津逗号规则硬套到中文。 不得把格式正确等同于事件真实、重要或已经获得媒体认可。
- 选择理由：该页用于 P13 的日期、数字、人名和引语一致性复核，不用于决定事件角度或事实强度。
- 研究说明：2026-08-17 逐页复审：检查 AP 标点、数字、职务、引语、标准组件和末尾格式问答。

### P13-B06｜PRSA guide to releases that get published

- URL：https://jobs.prsa.org/career-resources/finding-talent-10/how-to-write-a-press-release-that-actually-gets-published-377
- 来源类型：`professional_guidance`
- 语义焦点：可发布新闻稿如何从编辑需求反推信息顺序
- 页面结构：文章用六条摘要先给出标题、倒金字塔、篇幅、记者匹配、格式与分发，再依次展开标题、导语、正文、引语、公司简介和传播。 末尾把新闻价值、结构、发布时间等高频问题做成 FAQ，正文同时穿插品牌案例和传播效果数字。
- 观察到的子问题：标题是否突出外部影响而非只说公司做了什么？ 如果编辑从文末删减，最关键的事件事实和意义还能完整保留吗？
- 证据位置：导语被限定为 5W 事实摘要，正文才补行业背景、数据和有解释力的引语。 多个阅读率、互动率和媒体采用案例没有稳定的一手出处，不能转成 P13 的量化依据。
- 视觉作用：页面包含六步框架图、视频和通用头图，也建议附高清照片及采访机会。 可借鉴媒体资料提示，不复刻其 SEO 插图、品牌案例画面或效果倍数。
- FAQ 观察：有独立 FAQ，讨论何谓新闻价值、篇幅和发布时点；P13 可保留真正影响事件使用的问题，删除作者分发技巧。
- 优点：强调标题写外部影响，并说明倒金字塔为何能承受编辑删减。 把导语、正文、引语、公司简介和联系人各自的用途区分清楚。
- 局限：页面出现大量精确传播比例与成功故事，却未为每项提供可追溯方法。 写作建议、平台推广和课程资源混在一起，编辑需主动缩减。
- 不可借鉴：不得复用页面里的融资、诊所、软件危机等案例及其报道结果。 不得引用未经回查的阅读比例、多媒体倍数、记者偏好或最佳时段。
- 选择理由：该页可强化 P13 的外部影响标题和可删减结构，同时是识别伪精确营销数据的反面检查样本。
- 研究说明：2026-08-17 逐页复审：阅读六步摘要、标题、倒金字塔、正文、引语、分发与 FAQ，并核对案例证据位置。

### P13-B07｜GitHub press-release boilerplate

- URL：https://gist.github.com/ttscoff/3805575
- 来源类型：`github_repository`
- 语义焦点：轻量新闻稿模板如何保证基本字段不遗漏
- 页面结构：这是一份面向应用版本发布的单页 Markdown 模板：发布标识、版本标题、摘要、地点与开发者导语、新功能清单、反馈、价格与链接、开发者简介、采访联系人。 模板把新版真正变化放在中段清单，并把价格、商店、更新日志和联系人集中在尾部，适合小型产品更新。
