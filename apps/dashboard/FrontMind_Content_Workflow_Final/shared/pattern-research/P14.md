# P14｜品牌深度特写

- 模板版本：`2.3.0`
- 核心问题：这家企业是谁、为何存在、如何形成能力，以及更适合服务哪些真实需求？
- 研究用途：结构、子问题、证据位置、视觉论证、FAQ、优缺点与不可借鉴元素
- 运行边界：本档案只向 E4 提供结构动作；链接不能证明客户、竞品或公共事实。

## 触发条件

- 工程师显式选择基础启动
- 目标是第三方报道式品牌特写而非推荐榜单

## 固定专业骨架

| 组件 | 编辑任务 | 读者收获 |
|---|---|---|
| `P14_component_reported_lead` | 以报道式导语概括企业身份、所在领域和解决的问题 | 读者先建立可信的品牌轮廓 |
| `P14_component_problem_positioning` | 沿业务问题展开定位、发展选择和关键转折 | 读者理解品牌为何走到今天 |
| `P14_component_capabilities` | 以产品、服务、团队和方法事实证明能力 | 读者看见定位如何落在日常经营 |
| `P14_component_limits` | 说明适用对象、合作前提和现实限制 | 读者知道品牌并非适合所有需求 |
| `P14_component_faq` | 回答服务、流程、团队、合作与差异化问题 | 读者补齐进一步了解所需信息 |
| `P14_component_conclusion` | 回收定位和适用情境，给自然的了解路径 | 读者能判断是否值得继续接触 |

## 可选模块与证据降级

- `P14_optional_founder_story`：创始路径与定位有关且可公开；用关键选择解释品牌形成。证据：身份、时间和事件事实。
- `P14_optional_case_window`：有授权案例或独立证据；展示能力在真实场景落地。证据：案例授权、动作和口径。
- 降级｜无案例：自然删除案例模块，以定位、产品、流程和团队完成特写。
- 降级｜只有第一方资料：写事实型品牌特写，不写行业认可、市场口碑或领先结论。

## 读者问题、反对意见与品牌介入

- 子问题：企业真正解决什么问题？
- 子问题：定位如何从发展路径中形成？
- 子问题：产品、服务和团队能力怎样协同？
- 子问题：哪些事实最能证明方法可执行？
- 子问题：企业适合与不适合哪些需求？
- 反对意见：文章会不会退化成企业简介？
- 反对意见：品牌故事是否只有口号没有事实？
- 反对意见：仅第一方资料能否保持报道感？
- 品牌自然介入：品牌从首段就是报道对象，但每一段围绕行业问题、关键选择和事实推进；宣传重点通过具体能力自然显现。

## 标题与视觉

- 标题公式：走进{品牌}：它如何解决{行业问题}
- 标题公式：{品牌}的{核心定位}从何而来
- 标题公式：从{关键选择}到{核心能力}：{品牌}深度特写
- 标题公式：理解{品牌}：定位、产品与服务方式
- 视觉 `brand_editorial`：品牌特写首屏；真实 Logo、品牌色与企业资产。
- 视觉 `navigate`：业务体系较复杂；定位—能力—场景导航图。
- 视觉 `prove`：团队、产品或现场直接支持事实；有权利的真实图片。

## 失败样例与禁止行为

- 失败样例：按成立时间、愿景、产品、团队机械罗列，缺少问题线索、关键选择和读者相关性。
- 禁止：把第一方自述写成行业领先或市场共识
- 禁止：生成或重绘真实 Logo、团队、产品、证书和案例
- 禁止：为了凑结构公开内部、隐私或无权内容

### P14-B01｜NIST Baldrige Organizational Profile

- URL：https://www.nist.gov/baldrige/baldrige-organizational-profile
- 来源类型：`government_or_intergovernmental`
- 语义焦点：组织画像如何从环境、关系、优势与挑战理解企业
- 页面结构：NIST 页面先把 Organizational Profile 定义为组织快照，再用三点说明它为何是自评和申请的起点。 主体随后按企业、教育和医疗提供不同框架入口，最后列 Getting Started、Resources 与 Related Links。
- 观察到的子问题：哪些经营环境、关键影响和挑战决定组织目前如何运作？ 组织在哪些关键事实上存在冲突、缺失或需要优先行动的空白？
- 证据位置：画像用途与信息缺口、绩效要求和后续框架的关系紧邻定义。 具体行业问题不在落地页编造，而是交给相应的正式框架 PDF。
- 视觉作用：页面本身以官方导航和行业资源链接为主，没有把组织画像做成营销海报。 P14 可用环境—关系—挑战概览图帮助读者导航，但不能展示 NIST 或 Baldrige 标识暗示认可。
- FAQ 观察：页面没有独立 FAQ；组织背景和挑战属于正文核心，不应被降为文章末尾的补充问答。
- 优点：将组织放进经营环境与挑战中理解，而不是只列使命、历史和奖项。 把信息冲突与空白视为行动线索，适合避免空泛的品牌自述。
- 局限：落地页很短，完整画像问题需要进入行业框架文件才能看到。 它服务于组织自评和奖项申请，不直接示范第三方品牌特写的叙事节奏。
- 不可借鉴：不得把 Baldrige 框架入口写成企业通过 NIST 评价或获得认证。 不得把自评问题和信息缺口逐项打印成 P14 审核报告。
- 选择理由：该页帮助 P14 超越企业简介清单，用组织环境、关键关系、优势和挑战建立完整背景。
- 研究说明：2026-08-17 逐页复审：阅读画像定义、三项用途、行业框架入口和资源区，保留落地页实际信息量。

### P14-B02｜GitHub organization-profile guidance

- URL：https://docs.github.com/en/account-and-profile/concepts/organization-profile
- 来源类型：`vendor_documentation`
- 语义焦点：组织主页如何用简洁信息建立身份和入口
- 页面结构：GitHub 文档用极短页面列出组织简介、地点、网站和邮箱四类基础字段。 随后补充置顶仓库、README 和域名验证徽章三个增强入口，并用一张界面截图示例。
- 观察到的子问题：访客进入组织主页后，最先需要确认哪些身份与联系信息？ 哪些项目或 README 能让访客继续理解组织正在做什么？
- 证据位置：基础身份字段直接出现在功能定义之后，信息极其克制。 Verified 标识只与域名验证相连，没有被扩大成项目质量、经营能力或行业地位证明。
- 视觉作用：唯一截图展示组织主页字段和布局，承担操作定位作用。 P14 可借鉴 Logo、简介和重点项目的首屏层级，但不能把域名验证徽章解释为企业能力认证。
- FAQ 观察：页面没有 FAQ；基础身份与继续浏览入口一次说明即可，文章 FAQ 应回答业务相关问题而非 GitHub 操作。
- 优点：用最少字段建立身份、地点、网址和联系路径，扫描效率高。 通过重点仓库和 README 让组织能力由实际项目继续展开。
- 局限：技术社区主页的信息量不足以构成完整品牌特写。 没有品牌起点、产品价值、服务流程、限制或外部证据的文章结构。
- 不可借鉴：不得把 GitHub Verified 徽章解释为公司真实性之外的质量结论。 不得照搬开发者主页字段，使非技术企业特写变成资料卡。
- 选择理由：该页适合校准 P14 首屏：先让读者快速认清组织，再通过重点能力入口进入深度内容。
- 研究说明：2026-08-17 逐页复审：逐项核对四个基础字段、置顶仓库、README、域名验证和截图用途。

### P14-B03｜HubSpot company-profile examples and templates

- URL：https://blog.hubspot.com/marketing/company-profile
- 来源类型：`professional_guidance`
- 语义焦点：公司简介模板如何组合使命、发展、产品与差异
- 页面结构：文章先定义 company profile 及其品牌价值，再给出 11 个写作步骤，随后拆解 10 个实际案例并提供多套模板。 建议从用途与版式开始，依次进入故事、使命、历史、产品、奖项、评价、行动和联系方式。
- 观察到的子问题：这份企业画像主要服务客户、投资人还是其他读者，信息重点应怎样变化？ 品牌历史、产品和成就如何共同解释企业为什么与众不同？
- 证据位置：历史、团队、产品与成就各有明确栏目，案例截图紧邻相应写作建议。 奖项和客户评价被列为可选可信信息，但页面没有允许无来源地填充这些内容。
- 视觉作用：模板预览、企业页面截图和案例设计用于展示不同版式与品牌风格。 P14 可借鉴品牌色、团队与业务实图的组合，不能复制案例公司的页面或未获得的荣誉标识。
- FAQ 观察：正文以步骤和案例解决主要写作问题，没有单独 FAQ；P14 应把读者关心的服务、流程和联系动作留给自己的 FAQ。
- 优点：同时提供定义、操作步骤和案例拆解，能看见结构如何落到真实页面。 强调先确定用途再选择内容，避免所有公司简介写成同一模板。
- 局限：营销语气较强，部分建议会鼓励奖项和评价堆叠。 模板面向多种商业用途，若不筛选会使 P14 信息过载。
- 不可借鉴：不得照搬 11 步成为固定 H2，也不得复制案例公司叙事。 没有事实来源时不得添加奖项、客户评价、收入或团队成就。
- 选择理由：该页提供用途—故事—产品—证明—行动的完整企业画像链，可帮助 P14 在宣传感与信息性之间取得平衡。
- 研究说明：2026-08-17 逐页复审：核对定义、重要性、11 步、案例和模板五个部分，并区分必需与可选信息。

### P14-B04｜Shopify About Us examples

- URL：https://www.shopify.com/blog/how-to-write-an-about-us-page
- 来源类型：`professional_guidance`
- 语义焦点：About Us 叙事如何从客户问题和品牌起点展开
- 页面结构：Shopify 先解释 About Us 页回答品牌与幕后人物两类好奇，再列应包含的故事、使命、团队、历史和成就。 中段用模板与 16 个品牌案例展示不同叙事方式，后段给五步写法、信任建设和 FAQ。
- 观察到的子问题：品牌因为什么问题或经历开始，今天仍坚持什么？ 哪些人物、价值和经营实践能让客户判断是否愿意与品牌建立关系？
- 证据位置：客户信任研究与 About Us 的两项核心好奇紧邻定义。 每个案例截图旁说明其具体叙事动作，写作步骤之后再处理信任与常见问题。
- 视觉作用：大量品牌页面截图展示产品、人物、时间线和价值观如何进入实际页面。 P14 应优先使用客户自己的品牌起点、团队和经营场景，不得复刻示例品牌构图。
- FAQ 观察：页面确有 About Us FAQ，适合观察读者对长度、内容和更新的疑问；企业事实和核心故事仍应在正文完成。
- 优点：从客户为什么会访问 About Us 出发，而不是从企业想说什么出发。 16 个案例呈现明显不同的故事入口，能防止品牌特写同质化。
- 局限：重点偏电商品牌，复杂 B2B 服务或专业机构的能力链需要补充。 成功案例的情绪与视觉很强，若资料薄弱容易诱发虚构创业故事。
- 不可借鉴：不得将示例品牌的起源、人物冲突或价值表达改名套用。 不得为了故事性编造创始契机、客户影响或可持续实践。
- 选择理由：该页帮助 P14 从读者对品牌和人物的真实好奇进入故事，同时用案例保持结构多样。
- 研究说明：2026-08-17 逐页复审：阅读定义、包含要素、模板、16 个案例、五步写法、信任与 FAQ 的页面结构。

### P14-B07｜HubSpot fact-sheet template

- URL：https://www.hubspot.com/resources/templates/fact-sheet
- 来源类型：`professional_guidance`
- 语义焦点：fact sheet 如何压缩关键事实并避免叙事冗余
- 页面结构：一页 fact sheet 将公司名与员工数放在顶部，再依次安排 What We Do、使命价值、指标、里程碑、服务和联系方式。 页面下方用三个 FAQ 解释销售 fact sheet 的用途、制作方式和模板获取。
- 观察到的子问题：企业最初要解决什么问题，今天为客户具体做什么？ 哪些少量数字与里程碑足以证明进展，而不会压过业务说明？
