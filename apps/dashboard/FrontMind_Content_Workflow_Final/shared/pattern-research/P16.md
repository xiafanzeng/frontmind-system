# P16｜事实澄清与风险回应

- 模板版本：`2.3.0`
- 核心问题：针对明确错误信息或风险事件，哪些事实已经确认、影响谁、已采取什么行动、下一次何时更新？
- 研究用途：结构、子问题、证据位置、视觉论证、FAQ、优缺点与不可借鉴元素
- 运行边界：本档案只向 E4 提供结构动作；链接不能证明客户、竞品或公共事实。

## 触发条件

- 存在可指认的错误事实、争议或风险事件
- 需要即时澄清、响应或状态更新

## 固定专业骨架

| 组件 | 编辑任务 | 读者收获 |
|---|---|---|
| `P16_component_fact_lead` | 首段说明已确认事实、受影响对象和当前状态 | 读者先获得明确、及时的答案 |
| `P16_component_confirmed_unknown` | 分开呈现已确认、正在调查和已排除事项 | 读者不会把未知当事实 |
| `P16_component_timeline_impact` | 按时间重建事件并界定影响范围 | 读者能理解事情如何发展 |
| `P16_component_actions_status` | 说明处理动作、负责人、效果和当前进度 | 读者知道问题是否得到控制 |
| `P16_component_user_support_updates` | 给用户检查、支持渠道、补救方式和下次更新时间 | 受影响者知道现在该做什么 |
| `P16_component_faq` | 回答影响、数据或安全、补偿、恢复和后续通知 | 读者补齐最关心的响应问题 |
| `P16_component_conclusion` | 回收事实、影响和下一步，不用公关口号代替信息 | 读者留下可验证的状态认知 |

## 可选模块与证据降级

- `P16_optional_correction_table`：错误说法有多个具体断点；逐项给原说法与已确认事实。证据：原始说法和可靠事实来源。
- `P16_optional_incident_timeline`：事件跨多个节点；按时间解释发现、响应和恢复。证据：带时区的真实时间记录。
- 降级｜调查尚未完成：明确当前已知、未知和下次更新时间，不猜原因。
- 降级｜影响范围未确定：给自查与支持动作，避免写无影响保证。

## 读者问题、反对意见与品牌介入

- 子问题：错误或事件具体是什么？
- 子问题：哪些事实已经确认、哪些仍未知？
- 子问题：影响范围和时间线如何？
- 子问题：当前采取了哪些处理动作？
- 子问题：用户怎样自查、求助并获得更新？
- 反对意见：企业是否在回避关键事实？
- 反对意见：未知事项会不会被弱化成没有风险？
- 反对意见：补救和更新时间是否具体可执行？
- 品牌自然介入：品牌作为责任主体直接说明事实和行动，减少愿景与态度段；最重要信息按受影响者需求排序。

## 标题与视觉

- 标题公式：关于{争议事项}的事实说明与当前进展
- 标题公式：{事件}情况更新：影响、处理与下一步
- 标题公式：回应{错误说法}：已确认事实一览
- 标题公式：{品牌}发布{事件}最新状态
- 视觉 `navigate`：信息随时间更新；事件时间线或状态图。
- 视觉 `explain`：用户动作分支较多；自查—求助—更新流程图。
- 视觉 `prove`：需展示已发布更正或状态；真实公告、状态页或带来源数据。

## 失败样例与禁止行为

- 失败样例：用道歉、重视和价值观占据正文，却没有已知事实、影响范围、处理动作和更新时间。
- 禁止：隐瞒已确认的不利事实
- 禁止：把调查中事项写成已排除
- 禁止：虚构时间线、影响范围或恢复进度

## 公开标杆的可迁移动作

### P16-B01｜CDC Crisis and Emergency Risk Communication manual

- URL：https://www.cdc.gov/cerc/php/cerc-manual/index.html
- 来源类型：`government_or_intergovernmental`
- 语义焦点：危机沟通手册如何组织首报、更新、行动和同理心
- 页面结构：CDC 入口页先用一句话定义 CERC 的适用场景，再把手册拆成危机原则、心理、消息与受众、社区参与、沟通计划、发言人和媒体协作七章。 每章只给用途摘要和最后更新时间，页面承担知识导航，不直接提供某起事件的回应稿。
- 观察到的子问题：当前回应处于危机哪个阶段，受众此时怎样接收和判断信息？ 社区、发言人和媒体分别需要什么消息与参与方式？
- 证据位置：手册被明确标为循证框架，各章节更新时间与主题说明直接相邻。 页面没有客户事件、处置结果或单一标准话术，不能把章节摘要当具体事实。
- 视觉作用：入口页只有手册封面图和章节导航，视觉不承担事件证明。 P16 可借鉴阶段与受众关系做内部路线图，不能移植 CDC 标识或封面。
- FAQ 观察：没有 FAQ；七章导航说明不同问题应进入对应专业模块，公开回应只选与当次事件相关部分。
- 优点：把心理、受众、社区、计划、发言人和媒体放在同一危机沟通体系中。 各章更新时间公开，便于判断某项建议的时效。
- 局限：入口摘要非常短，无法单独决定消息内容或行动步骤。 框架服务美国公共卫生和重大灾害，不是一般企业争议的现成模板。
- 不可借鉴：不得把 CDC 循证框架描述成对客户回应或处置质量的认可。 不得复制官方封面、标识，也不得在未读章节时扩写其具体结论。
- 选择理由：该页适合为 P16 建立危机阶段与沟通角色的总导航，并提醒蓝图按事件需求选择模块而非一次塞入全部规则。
- 研究说明：2026-08-17 逐页复审：打开 CDC 手册入口，核对七章主题、适用说明与各章更新时间。

### P16-B02｜CDC analysis of an errant emergency warning

- URL：https://www.cdc.gov/mmwr/volumes/68/wr/mm6807a2.htm
- 来源类型：`government_or_intergovernmental`
- 语义焦点：错误警报复盘如何用时间线解释决策、影响和改进
- 页面结构：MMWR 先用已知信息、新增发现和公共卫生意义三问给出摘要，再按误报发生与撤回的分钟级时间线进入社交媒体研究。 方法、早晚两个时段、主题变化和讨论依次展开，最后列局限、改进建议、参考文献与主题表。
- 观察到的子问题：错误信息何时发出、何时纠正，延迟期间公众在处理、核验和行动上遇到什么问题？ 纠正之后出现了哪些新反应，流程中缺失了哪些确认和全清步骤？
- 证据位置：事件时间、样本数量、排除规则、搜索词、编码方法和软件版本都紧邻方法与结果。 主题变化由早晚两个同长时段的推文分析支持，流程原因另引 Hawaii EMA 与 FCC 调查。
- 视觉作用：主题对照表把早期与纠正后的反应并列，属于 prove 视觉；官方页另提供可打印 PDF。 P16 可重绘确认—纠正—行动缺口时间线，不复制推文原句或含个人账号内容。
- FAQ 观察：没有 FAQ；核心行动缺口在讨论和建议中解决。品牌回应可把个人自查与求助放入 FAQ，但不能重复整段事件复盘。
- 优点：把事件、纠正延迟、公众反应、流程缺陷和改进行动放在可追溯时间线上。 同时披露样本排除和主观编码局限，没有把社交反应外推为全部公众态度。
- 局限：研究只分析一个平台的公开发帖，且发生在特定地区与极端警报场景。 它是事后研究报告，不示范组织在事发当时如何逐次发布更新。
- 不可借鉴：不得复用具体推文、恐慌描述或导弹事件细节制造客户危机戏剧性。 不得把夏威夷流程缺陷、时间或研究结论套到其他组织和风险。
- 选择理由：该研究为 P16 提供少见的分钟级误报—纠正—信任后果结构，适合强化时间线、已知事实和公众行动信息。
- 研究说明：2026-08-17 逐页复审：阅读摘要、误报时间线、两时段方法、主题结果、流程调查、局限与主题表。

### P16-B03｜CDC crisis-communication planning guide

- URL：https://www.cdc.gov/cerc/media/pdfs/CERC_Crisis_Communication_Plans.pdf
- 来源类型：`government_or_intergovernmental`
- 语义焦点：危机计划如何预设角色、渠道、审批与信息节奏
- 页面结构：PDF 先按危机前、初始、维持、解决和评估阶段说明信息目标，再讨论沟通职能如何进入总体应急决策。 计划部分列最小组成、简洁可用原则和定期更新责任，随后给出九步建设流程、清单与工作表。
- 观察到的子问题：信息不完整的初始阶段，哪些事实已知、哪些仍在确认、下一次何时更新？ 谁核实、谁批准、谁发布，哪些渠道、合作方和非工作时间联系人必须预先确定？
- 证据位置：每个危机阶段的沟通目标紧邻该阶段的信息状态和公众需求。 责任、核实、快速审批、发布权限、发言人、合作渠道与联系人以最低计划要素清单呈现。
- 视觉作用：危机阶段示意、检查清单、现实提醒框和工作表承担 navigate 与 explain 作用。 P16 可重绘本组织的角色—渠道—更新时间图，但不复制 CDC 版式或机构联系人结构。
- FAQ 观察：手册通过阶段性公众问题和工作表处理预案，不设置文章 FAQ；实际回应只应回答当事人当前行动与更新渠道。
- 优点：明确初期信息会不完整，要求承认变化而不是过度安抚或猜测。 把沟通纳入应急行动本身，并为核实、授权、渠道和更新指定责任。
- 局限：章节最后更新于 2014 年，渠道、平台和部分组织安排需要结合现行环境复核。 内容面向公共卫生大型响应，完整预案对普通品牌事件可能过重。
- 不可借鉴：不得把预案占位语直接作为真实危机声明，也不得虚构跨机构协议和发言权限。 不得照搬美国联邦、州与地方应急组织结构到不适用地区。
- 选择理由：该 PDF 为 P16 提供从不完整初始信息到事后评估的阶段骨架，并明确一份可执行沟通计划最少需要什么。
- 研究说明：2026-08-17 逐页复审：下载官方 PDF 并检视五阶段目标、计划最低要素、简洁原则、更新责任和九步流程。

### P16-B04｜FEMA risk and crisis communication summit report

- URL：https://www.fema.gov/sites/default/files/documents/fema_risk-communications-crisis-communications-community-engagement-summit-report-2024.pdf
- 来源类型：`government_or_intergovernmental`
- 语义焦点：跨机构峰会如何处理风险沟通和社区参与
- 页面结构：峰会报告先交代 2024 年会议规模与三项互相关联的主题，再分别总结社区参与、风险沟通、危机沟通和跨部门协作。 各主题由演讲者观点、行动清单、现场照片和具体公共工具穿插说明，末尾汇总资源并邀请加入沟通者网络。
- 观察到的子问题：社区在危机前是否参与消息设计，哪些历史、文化、语言或资源因素影响信任？ 警报是否同时说清来源、风险、时间、地点和保护行动，并通过可信本地渠道到达？
- 证据位置：会议日期、地点、协办方、演讲与参与人数放在开篇，行动要点归入对应专题。 IPAWS、ESF #15 和消息设计工具以实际公共项目出现，但报告不提供这些做法的独立效果评估。
- 视觉作用：大量现场人物照片、署名图注与分栏清单表现峰会过程，另以工具截图和警报体系解释应用。 P16 可借鉴图注和多方角色呈现；不得使用 FEMA 标识、现场照片或将峰会规模当客户能力。
- FAQ 观察：没有 FAQ；报告用主题清单和资源页回答专业读者。实际风险回应应将本地行动、语言版本和求助入口置于正文或简短问答。
- 优点：将社区参与放到风险消息之前，强调消息由本地需求、信任和语言环境共同塑造。 把风险沟通与危机沟通区分为事前理解和事中紧急行动，边界清楚。
- 局限：它是峰会总结，观点多来自演讲与经验，缺少统一研究方法和成效比较。 美国联邦协调体系、警报平台和机构职责不能直接迁移到企业回应。
- 不可借鉴：不得引用演讲者姓名、现场照片或联邦工具暗示客户与 FEMA 存在关系。 不得把会议倡议和演讲观点表述成已经验证的普遍因果结论。
- 选择理由：该报告补足 P16 的社区共同设计、可信信使与语言可达性，使回应不只停留在企业单向声明。
- 研究说明：2026-08-17 逐页复审：下载 FEMA PDF，核对会议背景、四个主题、行动清单、公共工具、现场视觉与资源页。

- 选择理由：该页为 P16 提供团队、分级、声明、审批、监测和复盘的连续动作，但必须剔除营销统计与不适用案例。
- 研究说明：2026-08-17 逐页复审：阅读角色表、四级风险、七步协议、首轮声明、审批、监测、复盘、培训推广和 FAQ。

### P16-B06｜Incident-management postmortem template repository

- URL：https://github.com/ghostinthewires/Post-Mortems-Template
- 来源类型：`github_repository`
- 语义焦点：事故复盘模板如何记录影响、时间线、根因和修复
- 页面结构：仓库 README 先说明复盘用于记录影响、原因、缓解和防复发，再链接到独立模板。 模板依次要求日期、作者、状态、一句摘要、影响、根因、触发、解决、发现、行动项、经验、详细时间线和支持材料。
- 观察到的子问题：用户受到了什么影响、持续多久，事件由什么触发又如何被发现？ 哪些行动负责缓解、修复和防复发，各自由谁承担且处于什么状态？
- 证据位置：影响段要求对象、功能与时间范围，解决和发现分别记录实际动作与监测渠道。 行动项表把类型、负责人和任务链接放在同一行，时间线则按统一时区记录关键变化。
- 视觉作用：支持材料专门容纳监控图、截图和命令输出，属于技术复盘的 prove 视觉。 面向公众的 P16 只能使用去敏且能解释影响的图；内部仪表盘、命令和人员信息不得公开。
- FAQ 观察：模板没有 FAQ；影响、原因和改进行动均在复盘主体完成，外部问答只补用户行动与支持渠道。
- 优点：把影响、根因、触发、发现和解决分开，避免一句技术原因解释所有问题。 行动项同时记录负责人和完成状态，能把复盘转成后续改进。
- 局限：这是个人维护的开源仓库，提交较少，模板不代表行业认证标准。 结构面向技术服务中断，不包含公众关切、补偿、法律通知和多语言沟通。
