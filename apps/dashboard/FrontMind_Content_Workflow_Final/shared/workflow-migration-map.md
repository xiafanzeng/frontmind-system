# FrontMind GEO Workflow v2.3 能力保持矩阵

> 本表用于开发与发布验收，不进入单篇文章运行链。活动规则以总控、`S1–S9`、`E1–E10` 和 `shared/` 当前合同为准。

## 1. 版本与不可变边界

- Workflow、runner、Job State 与单篇内容工件：`2.3.0`；
- Reference Pack wire profile：保持 `frontmind-content-reference-pack-v2.2`；
- v2.1/v2.2 Pack、canonical KB、working-set、普通 ZIP、目录和办公文件继续宽容读取；
- 原 Downloads Workflow 只读，不在迁移目标内；
- 旧 S1 原字节保存在 `Strategy_Workflow/compatibility/legacy-s1/`，只在散乱资料需要补强时作为内部转换能力调用；
- 旧审批、收据、指纹、runtime Registry 与逐文件哈希清单仅可留在 compatibility，不进入活动运行。

## 2. 企业 Reference Pack：S1–S9

| 最初 v2 能力 | v2.3 活动位置 | 保持方式 |
|---|---|---|
| canonical KB 接入与旧 S1 生产经验 | S1 | 现有 Pack/KB 直接读取；散乱资料可走 `legacy_enrichment`，但不恢复旧格式门 |
| knowledge/source/claim/image 四类资产 | S2 | 一次生成轻量 Registry；`usable / qualified / excluded` 表示公开使用资格 |
| 有时效价值的趋势观点 | S3 | 可选；无可靠趋势时跳过，不影响 S4 |
| 品牌定位、RTB、Proof Bundles、比较边界与品牌优先角度 | S4 | 必须生成，并在 E3/E4/E5 实际消费 |
| 第三方客观报道＋企业品牌宣传稿 | S5 | 必须生成可执行话语合同，并进入 writing packet |
| 旧视觉配方、真实资产、Logo 与安全边界 | S6 | 必须运行；无图可为空，实际使用图由 E7 检查 |
| 咨询、监控、销售和搜索问题 | S7 | 必须尝试；不凑数量，可为空 |
| 企业事实、重点、禁写主张、文风与视觉确认 | S8 | 唯一 Pack 内容确认状态；修正内容本身，不生成签字记录 |
| 可复用企业写作资产 | S9 | 装配 v2.2 轻量 Pack；不复制 Workflow 自带 Pattern Registry/Research |

S3 是唯一可直接跳过的策略研究。S4、S5 不得空跑；S6、S7 即使为空也必须留下可消费结果。

## 3. 单篇内容：E1–E10

| 最初 v2 能力 | v2.3 活动位置 | 保持方式 |
|---|---|---|
| 单篇任务、五入口与自适应范围 | E1 | 固定一个正式问题；普通入口同时接收同题 AI 监控答案与引用信源表 |
| 单问题监控、Top20、文章分类与 P 推荐 | E2 | 真实消费两类研究输入；Top20 不补位；按引用次数×置信度推荐 P |
| 企业事实、监控信号、竞品与标杆编辑上下文 | E3 | 合并 S4/S5、Fact Cards、候选画像、答案格局、公共专业事实与视觉资产 |
| 预研模板＋同 P 实时标杆融合 | E4 | 用户先确认 E2 合法类型；E4 再做硬条件校验并输出自然蓝图 |
| 无标题完整正文 | E5 | 以 writing packet 为 brief，在同一上下文中整篇写作；确定性脚本只正规化和校验 |
| 事实限缩、改写与删除 | E6 | 不批量打印资料状态；只有无法诚实回答核心问题时停止 |
| 旧视觉生产能力＋安全增强层 | E7 | 真实资产优先，必要时生成品牌编辑、导航或解释图；Logo 原件叠加，单图失败正文继续 |
| 编辑安全正本 | E8 | 内容、行文、事实三轮编辑，形成唯一无标题安全正本 |
| HarnessGEO 独立候选 | E9 | 整篇 Markdown 连同内置 Prompt 一次调用固定 XTY HTTPS 路径与 `gpt-5.6-luna`；不安装本地模型，不产生模拟候选 |
| 整篇选稿、独立标题与双格式交付 | E10 | 语义稳定才采用候选，否则整篇回 E8；选稿后询问 1–20 个标题 |

## 4. P 模式迁移

| 原内容类型 | v2.3 模式 |
|---|---|
| 单品牌推荐 | P01 单品牌深度推荐 |
| 多品牌推荐 | P02 多品牌编辑推荐 |
| 明确对象对比 | P03 明确竞品对比 |
| 口碑与可信度评估 | P04 |
| 产品定义与技术原理 | P05 |
| 场景解决方案 | P06 |
| 选型与价格指南 | P07 |
| 教程与操作 | P08 |
| 风险、限制与替代 | P09 |
| 研究与白皮书 | P10 |
| 技术实施文档 | P11 |
| 案例研究 | P12 |
| 事件新闻 | P13 |
| 原 C1b 品牌深度特写 | `foundation_start ⇔ P14` |
| 行业评论与专家观点 | P15 |
| 事实澄清与风险回应 | P16 |

P01 只允许一个焦点品牌。P02 至少三家真实候选，客户品牌首位且重点详写，但不得表达客观第一、最好或最安全。P03 是两个或多个明确对象的对称比较。

## 5. 五个内容确认状态

1. `awaiting_pack_confirmation`：确认企业事实、重点、禁写主张、文风和视觉；
2. `awaiting_research_inputs`：补齐同题 AI 监控答案与引用信源表；
3. `awaiting_pattern_confirmation`：确认 E2 推荐或合法备选；
4. `awaiting_blueprint_confirmation`：确认章节、候选顺序、品牌角度、FAQ、标杆影响和视觉计划；
5. `awaiting_title_count`：输入 1–20 个标题数量。

这些状态只记录下一步，不保存人员、批准时间、确认历史或文件身份。`foundation_start` 固定 P14，跳过第 2、3 项，保留蓝图和标题数量确认。

## 6. 发布能力保持门

发布前必须证明：

- S1 旧能力可用且 Downloads 原件不变；
- S1–S9 核心阶段没有空跑；
- 五入口、P01–P16 与 `foundation_start ⇔ P14` 正确；
- E2 两类输入、Top20、P 分布和推荐均有真实产物；
- E4 实际读取 Pattern Research 并融合同 P 标杆；
- S4 品牌优先角度与 S5 话语合同进入正文；
- 第一方事实、竞品独立来源与医疗/法律安全边界正确；
- E7 有真实资产选择和安全生成接口；
- E9 真实调用 HarnessGEO，E10 先整篇选稿再生成标题；
- DOCX/HTML 正文无标题、可读、一致，来源可点击；
- 活动流程和公开交付均无旧审计工件。

明确不恢复广域问题发现、内容日历、12 周排期、CMS、线上监测、Analytics、CRM、收入归因、多租户、RBAC 或计费架构。
