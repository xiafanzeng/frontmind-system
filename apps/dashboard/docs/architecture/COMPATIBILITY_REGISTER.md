# FrontMind 兼容层登记表

本表只登记仍会被生产代码执行的旧协议读取路径。新写入必须使用当前协议；新增兼容逻辑必须同时填写影响范围、退出条件和目标版本，不能以永久 fallback 的形式进入主流程。

| 兼容层                                 | 负责人              | 当前影响范围                                     | 可观测退出条件                                            | 目标处理                                            |
| -------------------------------------- | ------------------- | ------------------------------------------------ | --------------------------------------------------------- | --------------------------------------------------- |
| Knowledge Base v1–v3 历史归档读取      | Knowledge Base      | 旧 Skill 生成且仍需下载的历史 ZIP                | 生产 inventory 中旧 `skillVersion` 归档为 0，且保留期结束 | 删除旧 descriptor/leaf 解释分支，只保留离线导出工具 |
| Service entitlement compatibility mode | Service Portal      | 尚未完成 entitlement 回填的历史账号              | `pendingUserCount=0` 连续 30 天                           | 固定为 enforced，删除 compatibility 写入路径        |
| 旧 Monitoring 工作表名称映射           | Monitoring          | 没有当前模型元数据的历史导入表                   | 历史模板导入量连续 90 天为 0                              | 将转换器移入离线迁移工具，在线导入只接收当前模板    |
| Website v1 Knowledge Base 合同读取     | Website integration | 仓库仍支持 v1 包；线上数量须在首次切换前只读盘点 | v1 包无活跃绑定且法定保留期结束                           | 删除在线 v1 校验，仅保留只读历史展示                |

## 约束

- 兼容代码不得放宽租户、权限、凭据或幂等边界。
- 兼容读取必须有结构化计数或 inventory，不能凭日期猜测是否可删除。
- 回填完成后先关闭旧写入，再观察读取量，最后删除读取分支。
- 本表只记录兼容事实，不承担发布审批或人工归档功能。
- “待盘点”不能被解释为 0；首次生产切换必须补录真实 inventory 后才能启动删除倒计时。
