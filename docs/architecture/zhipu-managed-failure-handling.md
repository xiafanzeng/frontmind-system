# 智谱 Managed Agents 失败处理核查（2026-09-06）

## 结论

“服务暂时不可用、重试耗尽”不是品牌词专属错误。Dashboard 知识库的一次
节点修改也出现过相同的原生错误，后续全新任务已成功修改并发布。
当前品牌词三次 max 运行均在正式产物生成前失败；另一次保持原模型、
Skill、正式知识库和流程的 high 对照也失败。四次均没有可下载结果。
不能把有限验收样本换算成整体故障率，也不能据此断定所有长任务都会失败。

Website 之前两次现状评估同样返回 `unknown_error` / exhausted，但其原始
消息明确为“余额不足或无可用资源包,请充值。”，属于不同原因；充值后两份
评估及各自预测已成功。通用智能体两轮、正式知识库完整流程、应答逻辑两轮
及确认也已通过真实验收。

## 公开资料确认的含义

- [事件与流式输出](https://docs.bigmodel.cn/cn/managed-agents/events)：
  `session.error.error.retry_status` 区分 retrying / exhausted / terminal。
  `session.status_idle.stop_reason` 区分正常结束、等待动作和重试耗尽。
  `span.model_request_end` 提供单次模型请求的错误标记和用量。
- [常见问题](https://docs.bigmodel.cn/cn/managed-agents/faq)：
  模型与环境在创建会话时冻结；SSE 只传实时事件，断线需读取历史补齐。
  支持 `glm-5.3` / `glm-5.3-flash` 和 low / high / max。
  Managed Agents 使用标准 API 按量计费，不使用 Coding Plan 额度。
- [创建会话](https://docs.bigmodel.cn/cn/managed-agents/create-session)：
  会话可以持续数小时、跨多轮交互。没有查到“15 分钟必须结束”的限制。
- [概述](https://docs.bigmodel.cn/cn/managed-agents/overview#反馈与交流)：
  产品仍为 API 内测，官方提供内测交流群作为问题反馈渠道。
- [通用 API 错误码](https://docs.bigmodel.cn/cn/faq/api-code)：
  区分鉴权、余额、限流、访问量过大、参数和内部错误。但此次 Managed
  Agents 原生事件没有提供这些更细的 HTTP/业务码，不能直接套用某个原因。

搜索了公开错误描述，并核对上述官方资料；未找到足以解释本次三条会话
内部失败原因的已公布故障说明。通用的
[延迟优化建议](https://docs.bigmodel.cn/cn/best-practice/latency-optimization)
讨论减少输出与上下文，但这不是该原生错误的确定修复方案；本次不据此改写
用户要求保留的 Skill、知识库、160 条结果结构或模型配置。

## 实际证据与限制

前两次品牌任务分别运行约 16 分钟和 17 分钟。第三次于 06:49:39 UTC
收到同类失败，最后一次模型请求持续 9 分 20.468 秒。三次均以 `is_error=true` 结束，随后出现
`unknown_error`、服务暂时不可用、exhausted 和 idle/retries_exhausted。

第二次的 85 个工具结果均无错误标记。两次公开进度均已完成知识库读取和
网页研究，最后具体研究步骤不同。每个会话仅有三个输入包，无可下载产物，
没有正式 JSON 被解析器拒绝。无本地 interrupt/delete、清理任务或运行
截止时间的证据。单次 HTTP 请求的超时与上游会话运行时间不是同一个限制。

这些证据把故障定位到上游模型请求，不能进一步证明负载、内部超时、上下文
限制或某个模型缺陷，也不能从最后请求上报零 token 推断整段会话免费。

## 处理方式

1. **retrying：继续等待原任务。** 这是平台正在自动重试的通知，不应立即
   把业务流程判为失败或再创建一个付费任务。
2. **exhausted / terminal：保留真实失败。** 后续 idle 不能把它覆盖为成功。
   有产物时走原业务解析；没有产物时不能伪造成功或绕过原校验。
3. **连接中断：读取同一任务历史。** 恢复事件读取本身不重新发任务；已确认
   的会话继续使用其绑定凭据。写请求结果不明时不盲目重发。
4. **已确定失败且无结果：按用户操作全新重跑。** 已经执行了三次
   有界任务，使用原 Skill、正式知识库、模型和 effort；三次失败均保留。没有旧对话
   重建，也没有无限自动重试。
5. **持续同类失败：向智谱定位上游问题。** 可提供会话/模型请求 ID、时间、
   模型与 effort、错误类型和脱敏复现步骤。未自动向外发送日志或凭据。
   已完成一次 high 对照并仍遇到同类故障；不能据此声称降低 effort 已解决
   问题，或默默替换已绑定任务的配置。

## 本次发现并修复的 Website 兼容遗漏

原 Website 适配器只识别字符串 `retry_status: "retrying"`，而实际原生
事件也使用 `{ "type": "retrying" }`。对象形式会被提前转换为业务错误。
另一个问题是，终态失败后若接到 end_turn/idle，历史归一化会将最后状态
覆盖为 stopped。

修复统一识别两种 retry_status 形式，并在同轮历史和 SSE 消费中保留终态
失败，直到下一个已处理的用户消息或新运行事件。没有新增审批、业务门槛、
自动任务重跑或 Skill 修改。相关回归用例在修改前复现四个失败；修复后
Website 与 Dashboard 适配器的相关 Node 回归全部通过。

品牌任务使用的 Dashboard 适配器此前已经正确处理这两种形式，因此这项
Website 修复不能被描述为已解决品牌词上游服务故障。

## 运行时间与请求超时

旧的知识库 15 分钟运行超时规则在先前版本已经删除。本次继续排查发现并
删除了 Website 的 60 分钟运行截止，以及知识库状态未知/404 的 10 分钟、
等待/额度中断的 24 小时截止。暂时读取 ZIP 失败也不再因累计超过 10 分钟
而失败；继续读取同一任务，重试间隔最多 120 秒。

Website 的临时网络读取失败（含 HTTP 200 后正文读取中断、408、425、429
和服务端暂时错误）继续等待。写请求结果不明仍不盲目重发。上游明确取消、
删除、终态失败，以及不可重试的无效响应继续如实处理；初始 idle 或未知
状态不能单独证明失败。任务已正常结束但实际未交付有效业务结果时，仍走
原有结果校验与错误处理。这些修改没有取消网络连接超时、身份检查或
结果校验，也没有改写原 Skill 或模型配置。

前三次品牌失败任务的数据库
`result_deadline_at` 均为空，没有设置任务运行截止时间。原生错误发生在
智谱服务端，未找到本地主动中断请求。单次网络请求超时、SSE 连接寿命、
资源保留期和任务执行总时限分别处理，不能混为一个“任务超时”。

## high 对照的实际结果

仅验收账号通过原管理员 API 创建一次 glm-5.3/high 的全新品牌任务，随后
立即恢复账号原来的 max 默认配置。任务冻结在 high，原 Skill、正式 KB、
业务流程不变。07:40:28.859 UTC 智谱返回相同的 unknown_error / 服务暂时
不可用 / exhausted，随后 idle/retries_exhausted；最后模型请求历时
704.300 秒，以 is_error=true 结束。没有有效公开 JSON 或可下载产物。

此对照没有解决故障，也未发现本地运行截止或主动中断。当前本地修复已
在生产 2ef9e64 上线并通过健康及页面验收，品牌生成仍需智谱侧定位。
没有第五次付费重跑；没有改变其他客户的配置或向供应商发送材料。
