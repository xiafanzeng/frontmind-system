## 二、优先修复知识库业务链路

### 1. 修复上传批次生命周期

当前最严重的遗漏是：第二次补充资料可能复用第一次的预约、文件状态及派发结果。

- 执行器按冻结的项目范围、会话、reset revision 和 `clientRequestId` 区分独立批次；取得预约后绑定对应 build、generation、turn。
- 同一次上传的重试、重选和继续复用原批次；新的补充操作创建新批次和新预约。
- 完成后释放该执行器的文件、预约缓存、派发 Promise 和计时器，保留必要的最终展示状态。
- 初建、节点补充、缺失文件重选全部通过同一执行引擎；页面只提交命令和订阅状态。
- 切业务页继续执行；切账号、切企业项目或批准重置时，撤销旧执行器权限并中止请求。
- 补充“同一会话连续两次补充”“不同节点连续补充”“第一次完成后切页再补充”的真实接口回归。

### 2. 修复派发结果未知后的恢复

当前管理器会缓存失败的派发 Promise，状态检查后仍可能无法继续。

- 用持久化派发状态决定下一步，不能由一个已拒绝的 Promise 永久决定结果。
- 沿用现有 `operationKey`、`clientRequestId` 和派发锁：
  - 明确尚未发送：允许按原身份继续。
  - 已受理或已有任务：绑定既有任务，继续读取。
  - 已发送但结果未知：核对本次请求，保持“启动结果待确认”。
  - 明确失败：展示持久化原因及允许操作。
- `readyToDispatch` 只表示资料与控制条件满足，不能单独证明模型请求从未发送。
- 同一逻辑轮次不得重复创建模型任务；后续补充属于新的逻辑轮次，单独验证创建次数。

### 3. 补齐预约、上传和暂存的等待边界

现有文件传输已有超时和有限重试，但预约、暂存请求仍可能无限等待。

| 场景 | 最终行为 |
|---|---|
| 30 秒无传输或业务进展 | 发起一次真实状态查询，查询上限 10 秒 |
| 5 分钟没有字节增长 | 中止当前传输尝试，保留已确认资料，显示可继续操作 |
| 文件传完、预约或暂存等待响应达到 6 分钟 | 核对同一请求结果，不创建替代任务 |
| 服务端已保存文件 | 复用已有资源，只完成缺少的确认步骤 |
| 暂存已提交但响应挂起 | 状态核对确认后接续执行，废弃原等待分支，忽略迟到回包 |
| 可恢复网络失败 | 最多自动重试两次，间隔 1 秒、3 秒 |
| 权限、参数、摘要、重置冲突 | 不自动重试，显示具体处理方式 |
| 派发结果未知 | 只核对当前轮，不进入普通重试创建循环 |

预约响应丢失时，以同项目、同会话、同 `clientRequestId` 找回或幂等重放原预约。查询、重试和原请求之间采用单一执行控制，避免两条分支同时向后推进。

### 4. 统一状态、进度和用量

本轮已发现：同一任务的上传状态接口与观察接口可能分别显示“调研”和“整理”；停止状态也未完整进入用量查询。

- 上传状态、观察接口、进度卡、消息列表、执行区和用量接口使用同一套权威状态规则。
- 统一表达：预约、上传、确认、派发、调研、整理、完成、失败、停止和需要重置。
- 状态读取使用一致快照；真实业务变化更新 `uploadStatusVersion`，心跳只更新连接信息。
- 前端合并响应时校验项目、build、turn、generation、reset revision 和版本；旧响应不能覆盖新状态。
- 用量查询读取真实 `uploadControl`：停止且未调用时明确显示“上传已停止，未产生模型调用”。
- 按 `buildId + generation` 归集用量，展开保留轮次和调用明细；当前轮未调用与历史费用分开显示。
- 已发送但结果未知、Token 不完整、费用待结算都显示待确认或同步中。
- 上传期间保留已上传大小、总大小、百分比、确认文件数、耗时和逐文件错误；系统附件不计入客户文件总数。
- 100% 字节传输但未确认时显示“传输完成，等待确认”，不能提前展示模型调研。

修复本轮失败的整理阶段展示测试：在共享执行区域保留真实整理状态，移除重复或无意义提示；测试同时验证“不误报停止”和“整理阶段实际可见”，不能只删除断言。

### 5. 验证权限、停止和全新重置

保留已有正确实现，使用真实事务验证其边界：

- 默认项目、非默认项目、授权工程师均按实际 actor／owner 和项目权限定位记录。
- 使用预约冻结的凭据；正常轮换后仍合法的旧凭据可用，被撤销或无法解密时显示配置错误。
- 停止、继续和派发在同一业务锁下竞争；停止成功后，旧 attempt 不能继续提交、暂存或派发。
- 停止尚未确认时显示“停止结果待确认”；若派发先成功，展示实际阶段。
- 明确继续才生成新 attempt，并复用已经确认的文件。
- 批准重置后退役旧 build、turn、预约及执行指针，增加 reset revision，返回空白工作区。
- 旧上传、旧心跳、旧派发及旧模型结果不能写入新一轮；下一次初建使用新的业务身份。
- 保留正常状态同步与同任务结果核对，继续停用旧任务接管、快照重建和重新绑定入口。

### 6. 接口与兼容方式

沿用现有接口，不增加第二套任务系统：

- `GET /api/knowledge-base/turn/upload-status`：纯读取文件、业务阶段、控制状态、允许操作和结果核对信息。
- `POST /api/knowledge-base/turn/upload-control`：显式 `stop / resume`。
- `KnowledgeBaseObservationDto.runPhase`：统一业务阶段；`processingPhase` 保留兼容。
- 复用现有 `dispatchState`、`createAttemptState`、任务标识和完成回执，提供足够的信息判断派发结果。
- 延续现有表和 metadata，计划不新增数据库迁移。

## 三、真实验收方案与执行顺序

### 1. 先让确定缺陷能够复现

优先补充以下回归，验证修复前失败、修复后通过：

- 第二次补充误用第一次预约。
- 派发网络失败后，状态核对成功仍无法继续。
- 真实停止接口成功后，用量仍显示上传。
- 整理期间两个状态接口阶段不一致。
- 预约或暂存响应挂起后无法接续。
- 整理阶段提示缺失及上传提前显示研究。

关键权限、凭据、暂存和派发路径使用真实实现；供应商模拟仅用于控制明确的异常和回包时序。

### 2. 真实浏览器与后端联动

使用候选代码、隔离数据库、真实测试登录会话，覆盖初建、补充、重选三个入口。

- 在预约返回前、上传中、等待确认和派发中切页，再返回核对状态。
- 验证停止后刷新保持停止、明确继续后不重复上传或派发。
- 验证断网、慢传、空响应 400、确认回包丢失和旧响应晚到。
- 连续完成两次补充，核对不同批次的预约、文件、轮次和结果。
- 核对进度、执行区、成果栏和用量页是否表达同一个真实状态。

本轮浏览器连接超时，因此不声称这些检查已经通过。实施时恢复浏览器连接并核实有效测试登录；页面预览和接口拦截不能代替真实联动验收。

### 3. 完成一次真实模型闭环

已确认采用**新建专用测试项目**，允许正常测试模型消耗，不操作客户现有失败任务。

1. 在隔离验收实例中建立测试账号／专用项目，使用获授权的测试连接。
2. 执行测试重置，确认工作区为空，旧身份失效。
3. 准备 9 份有效资料，总量接近原场景的 159.6 MB；记录实际字节数、摘要和至少三项可核对事实。
4. 第一个文件确认后切到其他页面，确认剩余文件继续处理。
5. 全部客户资料确认前，模型创建次数为零。
6. 全部确认后，初建轮次只创建一次模型任务。
7. 观察真实调研、整理、校验和产物生成；完成业务要求的节点确认。
8. 读取节点正文和最终产物，验证包完整性，并抽查三项事实能追溯到资料或引用。
9. 核对当前代、当前轮的调用、Token、费用及结算状态。
10. 刷新后重新核对结果、过程与费用。
11. 在同一测试项目连续执行两次补充，确认各自形成正确的新轮次并得到对应结果。

任何一次失败都记录为该场景未通过，定位后修复；不能自动重建新任务掩盖失败。测试资料、账号、密钥和数据库不复制进入生产环境。

### 4. 检查与收尾顺序

依次完成：知识库缺陷修复 → 真实业务验收 → 布局及其他模块收尾 → 最终回归 → 发布。

最终源码运行：


MySQL 使用 required 模式，环境缺失必须失败。普通测试中的条件跳过单独说明，不能算作关键业务通过；最终修改之后重跑受影响检查，不以较早日志替代。

## 五、发布与最终交付

目标仍为 **`dashboard.frontmind.cn` 的 CN 生产部署**，发布 Dashboard、siteops-worker 和 monitoring-worker。

1. **发布一个完整 `main` SHA。** 合并已验证修改，使用现有镜像构建取得不可变 digest；Dashboard 与 siteops-worker 使用同一 Dashboard 镜像。当前 CI 主要负责构建镜像，因此本次代码测试与业务验收结果必须单独确认。
2. **停止所选服务，按需迁移。** 当前方案没有新增迁移，不执行数据库迁移或额外数据库写入；保留上一版镜像和运行配置。
3. **启动并验证。** 核对容器、健康、就绪、源码 SHA 和 digest；在生产专用测试项目中使用真实登录检查状态读取、停止／继续、成果栏和用量响应。失败时恢复兼容的上一版镜像。

最终交付分别列明：

- 已确认问题逐项对应的修复与验收结果。
- 自动化检查结果、失败及跳过说明。
- 真实浏览器和真实模型验收的项目、轮次、创建次数、产物与费用核对结果。
- 多视口截图及常驻成果栏验证。
- 生产 SHA、镜像 digest、服务状态和回滚版本。

**只有知识库真实闭环、最终检查和生产业务检查全部通过，才声明“修复完成并上线”。**
