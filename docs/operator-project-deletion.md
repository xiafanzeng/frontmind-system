# 企业项目删除

`enterpriseProject.delete({ enterpriseProjectId, expectedRevision })` 使用已有
`enterprise_projects.archivedAt`，不新增迁移。返回
`{ enterpriseProjectId, revision, deletedAt }`。界面永久移除项目，没有恢复入口。
项目内容、配置版本、监控结果、媒体订单、供应商事实和账户账本都保留。

只有账户本人、系统管理员或当前分配给该账户的交付管理员可以删除。
服务端在项目行锁内验证 revision，并将其加一。重复提交相同删除请求返回
相同结果；其他旧版本请求冲突。新建请求不能重放已删除项目；重命名和读取
也检查删除状态。

项目还有以下工作时拒绝删除，并返回具体中文原因：

- AI 已授权、运行中、状态不明或待成本核算的任务；知识库和内容制作的待执行/运行轮次。
- 运行中、排队、等待额度或需复核的监控执行，包括未结束的供应商尝试。
- 未结束的媒体订单，或尚有预留/冻结费用的订单。
- 建站及内容任务的排队、运行、状态不明或待处理操作。

空闲项目的监控计划在删除事务内暂停，保留历史计划发生记录。新任务受理与
删除共用企业项目行锁：AI 付费授权、智能体会话预留、手动及后台监控执行、
媒体提交、建站受理均检查持久化归属和删除状态。后台监控从既有监控项目
读取企业归属，不依赖请求上下文。项目删除后，旧页面恢复监控计划也会被拒绝。
账户级 FrontMind 通用智能体不受某个企业项目删除影响。

核算入口不检查删除状态：已发生费用的延迟上报仍可入账，退款和冻结资金
处理保留原流程。删除不改变余额，也不撤销已发生费用。

验收测试使用独立的、已更新至当前结构的本机 MySQL 数据库
`fm_project_deletion_acceptance_operator`；测试仅增加合成记录，不清空共享数据。
通过 `FRONTMIND_ENTERPRISE_DELETION_TEST_DATABASE_URL` 运行
`server/enterprise-project-deletion.test.ts`。覆盖权限、revision、重复删除、
受理并发、各类运行任务、监控暂停和过期请求。独立财务验收
`server/ai-billing-mysql.test.ts` 验证归档后拒绝新授权，同时允许既有任务延迟费用结算。
