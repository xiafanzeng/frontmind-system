# 操作员账户钱包与智谱成本核算

一个操作员账户的所有企业项目共用一个人民币钱包。问题监控、媒体发布和 AI 命令都锁定 `unified_money_wallets` 的同一账户行，余额、业务预留、异常冻结与累计支出不会再分成两个钱包。企业项目权限仍由服务端校验，切换项目不会转移资金。

## 金额与资金明细

- 余额精度为人民币 `0.0001` 元，数据库以整数保存；可用余额 = 余额 − 预留 − 冻结。
- 消耗只有三类：`monitoring` 问题监控消耗、`media_publishing` 媒体投放消耗、`ai` 智能体消耗。分类统计只累计实际 `consume` 账目，同时提供累计及滚动近 30 天金额。
- 充值、管理员调整、预留与释放仍列在“全部收支”；它们不会混入三类消耗统计或消耗筛选。
- `billing.summary` 返回共享钱包和分类统计；`billing.activity` 合并三种业务账本并按时间排列。原媒体钱包接口为了兼容业务页面保留，但读写同一个共享钱包。
- 两个充值入口使用全局 `payment_receipt_claims`，同一支付提供方交易号不能分别给监控和媒体订单入账。银行转账审核也遵守相同约束。
- Website 公开智能体属于平台成本，不会凭推测分配给某个操作员钱包。

## 智谱官方成本与扣费

价格版本 `zhipu-glm-5.3-2026-09-07` 引用[智谱官方价格](https://bigmodel.cn/pricing)：GLM-5.3 输入 ¥8 / 百万 token、输出 ¥28 / 百万 token、缓存读取 ¥2 / 百万 token。Managed Agents 的三个计数独立相加，不从输入量中再次扣掉缓存量。Low、High、Max 的金额由各自实际用量决定，不额外乘倍率或加价。

权威成本来自服务端读取的 `span.model_request_end.model_usage` 事件；SSE 和回调只触发读取。每个事件以会话 ID 和提供方事件 ID 去重，失败、取消以及延迟到达的实际用量同样计入成本。只保存身份、事件 ID、token 计数、价格版本和金额，不在成本表保存对话文本或密钥。

内部用纳元（`10^-9` 元）计算。扣入钱包时保留每个账户不足 `0.0001` 元的尾数，后续事件继续累加；不对每个请求向上取整。管理后台和前台 API 的成本字段以人民币返回，`costStatus` 为 `complete`、`partial` 或 `unknown`。缺少 token 计数、未知模型或未经确认的缓存写入定价显示未知/待核算，不伪造为零。

单个已完成会话的完整性由原生 token 总计与模型事件总计核对。账户近 30 天原生事件金额即使每条都已核定，仍标记 `partial`：已覆盖事件的金额精确，但历史任务仍可能补查，不能把目前捕获的事件金额声称为该 Key 的完整官方账单。此实现没有伪造提供方未开放的 Key 级账单接口。

历史会话的成本可以回填展示，已有用量不追扣。只有新命令在服务端成功创建 `ai_charge_commands` 授权后，其可归属的事件才会扣钱包。Website 的成本仅入成本表。迁移会把近 30 天的已知智谱任务加入补查队列。

## 预留、耗尽与恢复

1. 每次向提供方发送新命令前，以 `min(可用余额, ¥1)` 预留；可用余额小于等于零时拒绝发送。预留按命令确定性幂等，重试和并发不会重复冻结。模型价格不可用、账户/项目/凭据归属不符或计费配置未激活时也拒绝发送。
2. 命令消耗当前预留窗口的 80% 后，再补充至多 ¥1。每次记录补充后的预留窗口；不足 ¥1 的余额也可用于启动和补充，例如 ¥0.20 的初始窗口在已消耗 ¥0.16 时尝试补充。
3. 已无可用余额、成本无法核实或命令归属不明确时，请求提供方中断。提供方没有逐任务硬金额上限，中断和用量上报存在延迟；已经发生的后续实际成本仍会结算，可能形成欠款。欠款账户不能继续发送新命令，充值后恢复可用余额。
4. 只有权威终止/空闲事件、当前会话状态和完整 token 汇总相互吻合时才释放剩余预留。仍在运行的会话不会因旧的空闲事件被提前释放。成本未知或上游响应丢失时保持待核算，不能把浏览器关闭、网络失败或本地超时当作免单依据。
5. 明确未接受执行的提供方错误可释放预留并关闭该命令；它不能以同一命令键再次发送。新的明确用户操作使用新命令意图。响应丢失时不自动重复发送，仅在唯一权威用户事件与已冻结请求哈希吻合后恢复计费归属。

进程内调度器使用数据库租约协调多个实例，15 秒轮询活动任务，终态任务每 10 分钟复查延迟用量，失败后 60 秒重试。任务身份和凭据版本来自原始持久化操作；不会用后来切换的企业项目或新密钥替换历史身份。租约过期可以由下一实例接手。

运维可查看 `ai_usage_sync_targets.last_error`、`ai_charge_commands.state` 和 `ai_cost_events.cost_state` 定位待核算。当前没有手工“免除待核算”接口；不可通过直接释放预留或关闭计费绕过尚未核实的费用。

## 知识库暂停与显式继续

新建知识库和发送文字节点修改在接收/派发前检查账户可用余额，余额不足返回 HTTP 402。实际发送仍进行事务预留以防并发余额变化；仅替换本地图片、没有文字修改的节点动作不触发付费检查。余额提示提供账户链接，不自动跳转或重发。

运行中的初始 High 任务若余额耗尽，会先通过当前命令的持久化中断键请求停止，再把知识库保留为可恢复状态。原 build、turn、Working Set、会话、模型和推理档位保留；后台扫描不会因充值到账而自动发起新的付费消息。用户点击“已充值，继续原任务”后服务端校验账户、企业项目、原凭据版本和资金，并获取恢复租约。

如果原始 High 命令还没有发送，恢复只把原 turn 放回待派发队列，复用已创建的原始会话。如果已经发送，则以新明确意图向同一会话发一次继续消息。并发点击只认同一持久化意图。响应不确定时只拉取权威事件，唯一文本哈希与原冻结请求吻合时修复确认；没有唯一匹配就保持暂停，不能因用户重复点击而重发。提供方明确拒绝的意图可由下一次新点击替代。

成本暂停提供“核对费用并继续”。尚未核清时只唤醒费用补查，继续请求返回待核算；核对成功本身不会自动恢复知识库，需要明确点击继续。余额或核算再次中断时使用新命令的中断键，不能复用上一轮已确认的中断结果。

初始知识库、词库/优化问题、应答逻辑、内容/通用智能体及 SiteOps 经过 `createCredentialAgentClient` 或 `createDashboardAgentClient` 的计费适配器。Low 节点修改使用独立 `KnowledgeNodeEditProvider`，同样调用事务授权、原生用量核对与拒绝释放；该路径失败时保留原节点，用户充值后明确重新提交一次修改，不套用初始 High 的同任务继续。旧名 `siliconflow-kb-maintenance.ts` 当前执行归属文件清理；`_core/llm.ts` 的 Forge `invokeLLM` 没有调用方。Website 适配器只记录平台成本。

## 首次切换与回退边界

`0063_unified_account_wallet.sql` 新建共享钱包、不可变期初记录和持久化财务状态。它在 `unified_wallet_openings` 记录两份旧余额、预留、已消费及媒体冻结值，再合计写入共享钱包。旧钱包和业务账本保留。历史监控支付回执被登记到全局交易号表；已有其他订单占用相同交易号时迁移失败，避免静默重复入账。

`0064_ai_cost_accounting.sql` 新建命令授权、成本事件、AI 账本与补查队列。`unified_finance_state.activated_at` 和 `ai_billing_configuration.enabled_at` 使用数据库 `UTC_TIMESTAMP(3)` 记录实际激活时间，不能预填部署时间。配置保存 `mode='active'`、最多预留 `10000` 个钱包单位及补充比例 `8000` 个基点。

首次切换需要短暂停止 Dashboard 以及会写监控/媒体资金的所有工作进程，执行应用迁移，再启动同一财务版本的应用和工作进程。迁移期间支付回调依靠提供方重试；启动后现有订单、预留与冻结继续在共享钱包结算。启动前核对期初合计，启动后核对一份钱包在两类业务接口中的余额一致以及计费调度器能读取任务。

这些 SQL 保留旧表、没有删除历史账目，但**激活共享钱包后不能回滚到仍写旧双钱包的二进制**。旧表此后只是历史证据，不能把活跃余额复制回去或把 `mode` 改回旧账务。`minimum_runtime_version=2` 记录财务兼容基线，并不会让旧二进制自动理解该要求。

后续代码回退必须使用仍支持共享钱包、AI 成本入账和预留恢复的财务兼容构建。首次上线若没有这样的回退构建，应保持资金写入停止并修复前进；不能把“数据库变更为增量”误认为旧账务代码仍可安全运行。恢复整个数据库备份还需处理备份之后已经被提供方接受的支付和 AI 成本，不能作为普通代码回退替代。

## 验证

`apps/dashboard/server/ai-billing-mysql.test.ts` 在专用 MySQL 8.4 验收库执行真实 0063/0064 SQL 和实际仓库/计费服务，覆盖期初合并、跨业务支付重放、共享余额、并发预留、冻结资金、低余额启动、80% 补充、事件幂等、尾数、未知成本保留、失败与晚到用量形成欠款、历史不追扣、平台成本以及账户/项目归属。

同一套测试还用当前 Drizzle 类型建立最小知识库事务夹具，验证未发送 High 恢复、同会话 High 续接、并发租约、唯一丢失回执修复、未知发送不重试、明确拒绝的新意图、费用核对后显式继续、过期 worker 租约和免费图片动作。这部分不是完整知识库迁移测试；全量迁移快照和应用 UI 另行验证。

```sh
FRONTMIND_FINANCE_TEST_MYSQL_URL='mysql://root@127.0.0.1:33077/fm_wallet_acceptance_operator' \
```
