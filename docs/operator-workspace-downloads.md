# 企业项目内的文件下载与 PDF 缓存

原生文件下载、PDF 准备地址和 PDF 重定向均携带 `enterpriseProjectId`，同时保留旧交付项目参数。服务端按已验证项目中的客户账号读取文件；登录身份仍是操作员或管理员，不会把客户文件改成管理员所有。文件授权仍在仓储和原始文件解析器完成。

## PDF 缓存边界

新建的准备记录写入 `enterpriseScopeVersion: 1` 和明确的 `enterpriseProjectId`：UUID 表示企业项目，`null` 表示账号级用途。缓存 ID 同时包含账号、凭据或文件来源、交付项目和企业项目。同一外链在账号用途和不同企业项目中分别缓存，不共用准备状态或 PDF 字节。

状态查询、内容、下载令牌、重试和按所属文件清理都检查缓存归属。没有项目的请求不能读取项目缓存，企业项目不能读取账号级缓存；同一操作员切换项目也不能复用另一项目的地址。损坏、缺失必要字段或未知版本的项目元数据不产生新的访问授权。

后台任务从持久化 manifest 恢复项目，重新验证项目仍属于原账号且未归档。队列由另一个项目的请求触发、另一实例恢复任务或进程重启，都不会改变归属。发布 PDF 前再次验证项目。账号级任务显式清除可能遗留的企业项目上下文。共享存储的 claim、CAS 和不可变归属检查阻止旧写入者擦除或改写已冻结的项目。

## 历史缓存

旧外链缓存只有账号与 URL，无法证明企业项目来源，因此仅原账号的账号级用途可以读取；默认企业项目也不会自动获得访问权。需要在企业项目中使用该外链时，在该项目重新准备会创建独立缓存。

旧 `fileId` 缓存有权威文件来源，可以在原文件解析器成功验证当前项目后，使用共享存储 claim 和 CAS 将该历史缓存一次性绑定到已证明的项目。绑定后不允许回到账号用途或改绑其他项目。明确标记为账号用途的新缓存不适用这条兼容规则。

## 验证

测试覆盖真实 Express 认证链、项目上下文、凭据中间件、原始文件解析器、本地文件和实际 PreparedFileService；HTTP 验收包含管理员原生下载、客户下载、PDF 重定向、外链准备及下载，以及更换、遗漏、冲突项目参数和陌生账号的拒绝。

实际服务测试检查跨实例缓存读取、同 URL 的项目隔离、账号用途隔离、历史外链拒绝、历史文件按来源授权绑定、不可变项目写入保护、在其他项目上下文触发的后台恢复，以及无法恢复归属时零外部请求。测试中的项目仓储、外部下载响应和 PDF 渲染器使用本地替身，不访问生产文件或外部服务。
