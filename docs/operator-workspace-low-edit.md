# 知识节点轻量编辑

本次将已物化的 v5 知识库节点修订改为固定 `glm-5.3 / low / standard`。不需要重建已有 v5 知识库；初次资料研究和已经派发的旧工作流继续使用原协议。

## 新旧协议分流

- 新的 `/turn` 和 `/turn/reserve` 节点修订由服务器写入 `recovery.nodeEditMode = low_v1`，继续复用原有预约、附件暂存、幂等请求和后台恢复入口。
- 只有该服务器标记进入新流程。没有标记的已接受旧回合继续原工作流；初次构建和明确的本地 Logo 操作不转成文本编辑。
- 节点树提供本地选择入口，已确认和已发布知识库的节点可以重新进入编辑。选择不调用模型，不修改已发布快照或当前 Working Set 正文。修改保存为新内容版本，随后等待再次确认。
- 本地确认选择最早的剩余待处理节点，跳过已确认节点。重新打开的节点确认后，无需重做其他已确认内容。

## 模型边界与恢复

模型收到的用户消息仅含 `{currentNode, instruction}`，没有其他节点、Working Set、证据包、图片、研究要求或工作流文件。专用 Agent 固定 Low，`tools`、`skills`、`mcp_servers` 均为空；环境使用空联网白名单，并关闭包管理器和 MCP 联网。

事实依据仅限当前节点和用户本次明确提供的材料，不允许凭模型记忆补写事实、数据、案例或引用。缺少依据时保留相关原文，并在正文相应位置简短提示需要补充的材料；输出仍只有 `contentMarkdown`，不增加协议字段或触发研究。

每次文字修改使用新 Session。同企业项目、同账号、同凭证版本可复用此前创建的空编辑 Agent 和环境。没有文件上传、图片识别、GLM Flash 或自动 High/Max 升级。

每个创建和发送动作先写入持久化发送账本。丢失发送确认后，只读取原 Session，并按唯一正文哈希找回接受事件，不重发模型命令。原始模型用量事件交给统一钱包记账；恢复出的接受事件 ID 也会持久化，防止费用长期停留在待归属状态。

应用每两秒读取原 Session 的状态和事件；结束后立即校验与保存，不再等待旧的 30 秒恢复扫描。十分钟超时会发中断，不自动重跑。中断不是供应商的硬金额上限，已经产生的原价用量仍需结算。

## 本地图片与版本安全

纯图片回合使用空修改文字，创建模型任务和文件上传到供应商的次数均为零。支持上传图片、从当前项目已有上传图片选择、替换、移除。图片库只跨当前项目的活动 Working Set 选择，不跨企业项目读取。

本地上传和复用图片均校验内容哈希、字节数、MIME、实际图片解码结果与来源。复用图片必须属于当前 Working Set 的第一方上传记录。移除共享图片仅解除当前节点的引用，保留其他节点及图片字节。

模型只返回一个严格 JSON 对象，唯一字段为 `contentMarkdown`。重复键、代码围栏、空内容和额外字段均拒绝，不再让模型修复。应用生成确定性的本地 Patch ZIP，使用诚实的 `applicationAuthoredPatch` 来源标记；不会假称该 ZIP 是模型直接输出，纯图片回合也不伪造供应商任务 ID。

应用 Patch 必须绑定当前租约、回合、节点、版本、Working Set ID、包 SHA256 和附件来源证明。生成的新 Working Set 在行锁和 CAS 检查通过后激活，旧版本保留。校验或模型失败只释放本轮编辑，保留原节点并提示用户，允许重新提交，不要求重置知识库。
