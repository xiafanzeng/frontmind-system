# 操作员企业项目与历史迁移

账号仍是登录、凭据、账务和权限主体。每个账号可拥有多个企业项目；系统管理员可查看并操作客户项目，交付管理员必须有既有客户分配关系。没有新增团队、虚拟用户或无限额度套餐。所有操作员都启用相同三类交付岗位，历史套餐不再决定岗位可用性，实际人员分配仍须核验。项目授权在服务端核验，浏览器提供的项目 ID 只用来选择作用域。

## 请求与后台恢复

- JSON 请求通过 `x-enterprise-project-id` 选择项目。下载、图片和普通链接通过 `enterpriseProjectId` 查询参数选择项目；两者不一致或不是 UUID 时拒绝请求。
- `EnterpriseProjectScope` 同时记录 `ownerUserId` 和 `actorUserId`。业务内容、模型凭据和账户费用采用项目所有者，审计保留实际操作员。
- 普通通用智能体和账户页使用账户作用域。企业问答与内容制作任务冻结企业项目，后台恢复从已保存的操作或任务读取项目，不依赖浏览器当前选择。
- 项目查询严格匹配项目 ID，包括默认项目；NULL 仅属于账户级通用任务。历史资产根据已保存的附件、任务、对话、文件租约和站点输入关联迁入项目。
- 新项目的对话存储前缀为 `e<projectId>:`。迁移默认项目保留既有 `u<userId>:` 前缀以兼容历史对话 ID。
- 知识库恢复候选和清理任务保存项目 ID；恢复前校验项目与 owner，再运行 claim、派发、结果归并或失败回写。站点 worker 从权威站点项目行恢复相同作用域。
- 知识库成品 ZIP、站点源码、样式预览和社交归档链接保留企业项目查询参数。站点构建、样式和社交包读取同时约束项目所有者与父站点项目；管理员操作继续使用客户内容所有者。私有站点预览的页面跳转与 History API 保留该作用域，页面自身读取的规范 pathname 不变。
- 阿里云 OAuth 签名 state 冻结实际操作员、内容所有者、站点项目与企业项目。回调在兑换 code 前重新验证授权，绑定前再恢复保存的项目；浏览器切换项目不会改变授权目标。旧 state 只接受原账号，从持久化站点项目恢复迁移后的默认项目。连接完成不产生模型费用，因此不读取历史套餐；AI 操作继续使用统一余额计费。

## 0062 迁移

先运行既有 Dashboard 与监控数据库迁移，再应用 `0062_enterprise_operator_projects.sql`。该迁移只增加表、列和项目索引，并保留既有账户内容、问题、合同及服务周期表。

迁移为运行前已有账号建立一个确定 ID 的默认项目，将原账户内容、问题、知识库重置版本和站点资料复制到新的项目表。原内容和 revision 保留。知识库、已发布版本、应答逻辑、旧监控资料、站点、导入回执、清理任务及企业用途模型操作绑定默认项目。普通通用对话保持账户级。监控原 projects 通过既有 Dashboard/监控账户映射绑定默认企业项目。

新注册账号和管理员新建账号不会自动创建默认项目。用户首次进入后创建自己的企业项目。新账号不写入套餐合同或问题额度。历史合同字段只作历史来源记录，当前项目 portal 返回 `mode: operator`、`quotas: null`。

项目表成为新版服务的写入位置。旧表仍可供历史版本读取，但应用回滚不会把新版多个项目重新合并进单一旧账户内容；如需回滚，应先停止写入并保留新增表，不能删除项目数据或将其覆盖到旧账户行。

默认项目恢复迁移前的模型任务时，在严格 owner/project 限制内识别旧幂等键和请求摘要，并重用已有 provider session。新项目仍使用项目命名空间；同时发现旧、新两条重复任务时拒绝再次派发。永久账号删除按所有者清理全部项目关系，不能被当前浏览器项目筛选缩窄。

## 问题与监控衔接

`enterpriseProjects.createMonitoringProject` 接收企业项目 ID、名称、已选择优化问题 ID 和客户端请求 UUID。服务器在同一事务内验证问题所有权，冻结问题文本与 revision、品牌第 1 版，并创建底层监控项目。同一请求重放返回相同项目；换内容重用请求 ID 返回冲突。

问题后续修改采用替换历史问题的方式。监控链接中的原问题文本和 revision 不随修改变化；监控运行继续依赖原有不可变品牌/监控配置版本。平台、重复次数及计划沿用原有监控表单和服务端 500 次尝试上限。

监控项目、监控配置、运行、结果和导出读取通过父项目约束。`monitoringProgress` 汇总当前企业项目最近 200 次真实运行，明确返回窗口标记，并提供监控项目的冻结来源问题。账户钱包不受项目切换影响。

## 验证

`server/enterprise-project.test.ts` 包含请求参数冲突、owner 与 project 双重条件、旧默认项目兼容和并发异步作用域测试。可选 MySQL 验收只接受 localhost 上名称以 `fm_project_acceptance_operator` 开头的临时数据库，覆盖：

- 旧内容与重置 revision 的迁移、新账号空项目状态；
- 同一账户两项目隔离、其他账号拒绝访问、管理员保留客户 owner；
- 并发创建幂等、无套餐问题选择和修改；
- 监控链接快照在问题修改后不变、监控子记录按企业项目隔离；
- 后台恢复对 owner/project 不匹配的拒绝、默认项目重用旧 provider session；
- 其他项目与账户级通用任务无法读取该 session；
- 永久账号删除在一个项目作用域下仍正确删除该账户两个项目及外键关系。

运行示例（数据库须先准备既有迁移、测试账号及 0062 之后需要的账务表）：

```sh
FRONTMIND_ENTERPRISE_PROJECT_TEST_DATABASE_URL=mysql://root@127.0.0.1:33077/fm_project_acceptance_operator_clean pnpm --filter frontmind-client exec vitest run server/enterprise-project.test.ts
```

本组验收不调用外部模型、监控或媒体发布供应商，不代表供应商真实执行链已完成在线验收。媒体发布的项目隔离与统一账务分别由其领域实现和测试覆盖；此文档的数据库验收只列出本组实际覆盖范围。
