# Operator workspace corrections

Project management uses a compact menu for create, rename and delete. Delete
requires confirmation showing the project name, and has no restore entry. The
server retains historical records and account ledgers; active or uncertain paid
work must finish before deletion. See [project deletion](operator-project-deletion.md).

Navigation preserves enterprise and administrator parameters in normal clicks,
native links and publishing filter canonicalization. Project changes retire the
old query cache and abort its requests; account tools use account transports.
Multi-step REST requests freeze their original project before awaiting uploads,
reservations or retries. Unsynchronized conversation messages and attachments are
retained in page memory under their original account/project until that workspace
is opened again. This does not automatically dispatch a paid task.

General-agent admission errors preserve their real status and user guidance.
Insufficient balance before supplier dispatch returns a balance error; provider
rate limits remain 429, and genuinely uncertain submissions remain unresolved.
Old create records with durable before-send balance refusal and no supplier-send
mutation are recognized as rejected when read. No automatic paid replay or
production data repair is required. Other modules hide model/effort labels while
retaining their actual frozen execution profiles.

This release adds no database migration. Publish the coherent main SHA, use its
Dashboard and monitoring-worker image digests, stop the three selected services,
then start and check health/readiness and workspace navigation. Website remains
on its existing image. Recovery may use the immediately previous unified-wallet
release; never return to the older dual-wallet runtime.
